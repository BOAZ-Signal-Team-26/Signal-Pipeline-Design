# 06. 원본·정정본과 기준일 판정 — 2026-09-22 재검토안

원본과 모든 정정본은 보존하고 기준일의 대표본으로 채점한다는 기존 원칙은 유지한다. 대표본·판매 여부를 알 수 없는 상태를 확정값으로 만드는 규칙은 수정한다.

## 1. 공시 정정과 파일 버전

| 식별자 | 뜻 |
|---|---|
| document_id / (source, source_doc_key) | 소스에서 발행된 공시/접수/게시글 |
| lineage_id | 검증된 같은 사건의 최초 문서. 최초본은 self, 미확정은 NULL |
| raw_object_id / version_seq | 특정 첨부의 바이트 버전 |
| run_id | 입력·파서·산식·기준일을 고정한 실행 |

파일 해시가 같아도 서로 다른 공시일 수 있고, 같은 공시의 파일 바이트가 바뀔 수도 있다. 파일 변경을 자동으로 「공시 정정」으로 판정하지 않는다.

DART는 정정 구조와 최초제출일·상품/제출자 근거를 함께 확인한다. 접두어만으로 판단하거나 최초제출일 하나로 다른 펀드 문서를 합치지 않는다. 금투협 계보 규칙은 미정이므로 is_correction/lineage_id를 임의로 채우지 않는다. 최초본 미도착도 NULL로 보존한다.

## 2. 기준일의 대표본 선택

1. run.baseline_date와 입력 컷오프를 고정한다. 과거 자료 재현이면 당시 이용 가능했던 문서만 후보로 둔다.
2. 확인된 동일 계보에서는 기준일 이하의 최신 유효 문서를 선택한다. 현재 is_current=true라는 이유로 기준일 뒤 정정본을 선택하지 않는다.
3. 같은 fund_key에 소스/역할이 다른 문서가 여러 개이면 대표 역할(정식/간이)과 소스 우선순위를 적용해야 한다. 이 우선순위는 DS 인계에서 확정할 항목이다.
4. 날짜 동률·소스 충돌·금투협 계보 미확정은 임의 ID 순서로 최신본을 결정하지 않는다. 선택이 불가능하면 AMBIGUOUS_DOCUMENT 사유로 비교에서 제외한다.
5. 선택한 document_id뿐 아니라 raw_object_id/sha256, section_ids, 선택 이유를 입력·모집단 manifest에 저장한다.

문서가 2행이라고 꼭 펀드가 2개인 것도 아니고, 파일 해시가 다르다고 서로 다른 비교 관측치인 것도 아니다. 펀드당 대표본 하나라는 **분석 정책**을 실제 선택 단계에서 구현해야 한다.

원본과 정정본 점수 차이 분석은 가능하지만 현재값과 역사값을 섞지 않는다. CDI는 **높을수록 난독성이 높다**는 DS 문헌 검토 방향을 따른다. 정정이 이해를 돕는다면 CDI가 낮아질 수 있다는 가설이며, 실제 방향·크기는 측정 전 단정하지 않는다.

## 3. 판매 중 확인과 후보 범위

`inception_date=setpDt`는 설정일이다. 판매개시일의 확인된 원천으로 취급하지 않는다. sale_start_date/sale_end_date는 확인된 값만 넣는다.

| 분류 | 조건/의미 | 사용 |
|---|---|---|
| CONFIRMED_ACTIVE | 기준일의 판매/상장 근거가 확인됨 | 다른 자격도 충족하면 확인 범위에 포함 |
| CONFIRMED_INACTIVE | 유효한 종료/미판매 근거 확인 | 제외 |
| UNKNOWN | 시작/종료/당시 상태 근거 부족 | 후보 집계로 별도 보고, 판매 중 확정 분모에 몰래 포함하지 않음 |

이 상태는 현재 상품의 영구 boolean이 아니라 **실행 기준일별 판정**이며 입력 manifest에 판정·근거·관측일을 기록한다.

확인된 판매 기간이 있다면 시작 포함·종료 제외 `start <= baseline < end`를 기본 계약으로 제안한다. 원천이 마지막 판매일을 종료일로 주는 경우 포함 경계를 명시적으로 변환한다. end=NULL은 「종료일을 모름」이며, 독립적인 기준일 판매 근거가 없는 한 판매 중의 증거가 아니다.

KRX에서는 그 기준일의 검증된 거래일 자료에 존재하는 ETF를 관측할 수 있다. **어제 있었고 오늘 안 보인다는 이유만으로 상장폐지를 확정하지 않는다.** 휴장, API 실패, 응답 절단, 승인 문제를 먼저 배제하고 별도의 상장폐지 근거/정책을 확인한다. 이름 매칭 실패 229건도 상장폐지가 아니다.

현재 종료일 원천이 부족하므로 산출 범위는 「관측된 상품 후보 중 채점 가능 범위」와 「판매 중 확인 범위」를 구분해 표시한다. 목적의 전수성을 이미 달성했다고 보고하지 않는다.

## 4. 이력 요구

- 실행 입력 manifest에 당시 클래스→fund_key 연결, 분류·위험등급·판매 상태·문서 선택을 고정한다.
- 현재 product 갱신은 과거 실행의 속성을 바꾸지 않는다.
- SCD2 구현 시에는 버전 PK와 논리 product_id를 분리해야 한다. valid_from/valid_to 두 칸만 있는 현재 PK로 여러 버전을 적재할 수는 없다.
- 물리 DB·SCD 방식은 Gate B에서 정한다. 현재 설계의 불변 원본과 manifest는 그 결정 전에도 재현 근거를 보존한다.

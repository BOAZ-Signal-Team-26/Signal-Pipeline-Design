# 컨텍스트 브리프 — 1단계 데이터 테이블·ERD 설계 확정 (09-16)

작성일 2026-09-14. 기한 2026-09-16 (여유 0일). 담당 대현, 검토 주영. 이 문서는 두 작업 에이전트(data-engineer, data-scientist)가 공유하는 입력이다. 여기 적힌 사실은 Notion Epic·티켓 3건에서 그대로 옮긴 것이며, 임의로 바꾸지 않는다.

## 프로젝트 한 줄 정의
판매 중인 금융상품 설명서를 전수 채점해 설명 난독성 지도를 만들고, 그 기준을 비대면 가입 플로우에 적용해 개선안을 도출한다.

## 최종 산출물의 성격 (결정 완료)
- A 카탈로그형(전수 채점 파이프라인)이 본체다. 스키마는 A를 위해 설계한다.
- B 진단 도구형(문서 1건 → 점수·취약 지점)은 별도 업로드 기능이 아니라 **대시보드 드릴다운 화면**으로 흡수한다. 따라서 수집 층을 우회하는 진입 경로를 만들지 않는다. 드릴다운이 성립하려면 점수가 문서 단위가 아니라 **절 단위**로 저장되어야 한다.
- C 프로세스 개선안은 대상이 PDF가 아니라 앱 가입 플로우이고, 수동 1회성 분석이다. **스키마에 넣지 않는다.** 화면 순서 테이블을 만들지 않는다.
- CDI는 정규화 점수다. 「72점」은 단독으로 의미가 없고, 비교 모집단(동일 상품군·동일 위험등급) 안의 위치로만 읽는다. 따라서 상품 표에 층화 키가 있어야 한다.

## 09-09 확정 사항
- 상품군: 펀드, ETF, ELS.
- CDI 산출 대상: **펀드와 ETF만**. ELS는 CDI를 계산하지 않는다. ELS에 적용되는 점수는 고지 충실도 점수다(수동 라벨 200건으로 임계값 튜닝). → 점수가 두 종류이고 적용 범위가 다르다.
- ETF 식별 규칙: 상품명에 「상장지수」 문자열 포함.
- 소스 4종과 이어 붙일 값 후보:
  | 소스 | 조인 키 후보 |
  |---|---|
  | 금융상품통합비교공시 | `fin_prdt_cd` 계열 |
  | OPEN DART | `rcept_no`(접수번호), `corp_code` |
  | ~~공공데이터포털 증권상품시세정보~~ → **공공데이터포털 펀드상품기본정보** (09-20 정정) | ~~`ISU_CD`~~ → `srtnCd`·`asoStdCd`. **`ISU_CD`는 KRX에서 받는다.** 증권상품시세정보는 이 저장소에서 한 번도 열린 적이 없다. 09-09에 적은 소스가 실제 수집 대상과 다르다 |

- 분쟁조정 결정문(814건 중 금융투자 187건)은 상품명이 전부 마스킹되어 상품 단위로 이어 붙일 값이 없다.

## 스키마에 반드시 반영할 5가지 (티켓 3건 대조 결과)
1. 점수를 **절 단위**로 저장할 수 있어야 한다 (드릴다운 근거).
2. 점수 유형(CDI / 고지충실도)을 구분해 ELS 행의 CDI가 비는 구조를 피한다.
3. 「판매 중」 판정 시점 규칙과 원본/정정본 규칙을 정한다 (SCD 구현은 2단계 데이터 파이프라인 Flow 설계, 규칙은 지금).
4. 매칭 실패는 건수 집계가 아니라 **행 단위**로 실패 사유·실패한 키값·소스를 남긴다. (문자열 조인 실패가 ETF·특정 판매사에 몰려 표본을 한쪽으로 치우치게 하고, 조인에서 밀린 상품은 위험등급이 비어 잔차 회귀에서 통째로 버려지기 때문.)
5. 분쟁조정 결정문은 상품 표에 연결하지 않는다. 판매사 축 또는 별도 축으로만 붙인다.

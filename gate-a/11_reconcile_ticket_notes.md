# 11. 티켓 메모(00b) ↔ 초안 충돌 판정 기록

09-14 밤. Notion 티켓 두 곳의 검토 메모(00b)를 초안(01~10)과 대조했다. 방향은 대체로 같았고, 네 곳이 어긋났다. 판정은 읽기 전용 아키텍트 검토를 거쳐 대현이 확정했다. 기준: 09-17 수집 개발이 시작할 수 있는 최소 설계, 2단계 데이터 파이프라인 Flow 설계·C로 미룰 수 있는 것은 미룸, 되돌릴 수 없는 결정(표본 편향, 이력 소실)은 지금 막음.

## 네 충돌의 판정

| # | 항목 | 00b 권고 | 초안 | 판정 | 근거 |
|---|---|---|---|---|---|
| 1 | 문서 단위·문서:상품 | 문서 = 원천 문서 1건, 1:N 브릿지 | 문서.product_id 단일 FK | **채택** + 조건 | 브릿지 비용은 작고 단일 FK는 종류형 펀드를 담지 못한다. 조건: **상품 행 = 클래스**(short_code·srtnCd가 클래스 입자). 펀드 단위는 `fund_key`(클래스 표기 제거 본체명 + 운용사)로 파생하고, 04의 정규화 모집단은 fund_key로 중복 제거. 이것을 빠뜨리면 표본이 클래스 수에 비례해 실제보다 크게 나오고 사후 교정 불가 |
| 2 | 위험등급 산정 구조 | 산정 주체 칸 + 정량 9·정성 6 요소 | 등급 값만 저장 | **채택 안 함** | 요소별 값이 우리 소스 어디에도 없다(09: 표지는 「n등급[문구]」 결과값 하나). 산정 주체는 표지 = 집합투자업자 분류로 상수. 판매사별 등급 소스가 생기면 (상품 × 산정 주체) 행으로 바꾼다는 한 줄만 01에 남김. 00b의 사실 교정(4가지가 아니라 9+6, 원칙상 판매업자) 자체는 옳음 |
| 3 | 문자열 매칭 임계치 | 용도별 두 벌: DART 0.80 미만만 제외(재현율), 분쟁·제재 0.95+단독+판매사 일치 | 단일 표 0.85/0.60, 정밀도 우선 | **조건부** | DART용 재현율 벌은 채택하지 않음: 09에서 펀드코드 10/10이라 DART 문자열은 잔여 건 2차 수단이 되어 기존 수동 구간과 기능이 겹침. 분쟁·제재 엄격 규칙(0.95 + 단독 후보 + 교차 확인), 187건 전건 수동, 모·자 「자」·호수 하드 룰은 **채택**. 판매사 임계치 0.90 → 0.95 |
| 4 | 원본 저장 구조 | CAS `blobs/{sha256[:2]}/{sha256}` + 논리 경로는 칸에만 | 파일 경로 + 버전 누적 | **보류(2단계 데이터 파이프라인 Flow 설계)** | 근거인 「금투협 15행 = PDF 1개」가 09-15 실측 전이고 00b A7 스스로 반론을 기록. 원본이 불변인 한 재배치는 되돌릴 수 있는 결정. 지금은 원본파일 표의 sha256 칸 + 「같은 해시면 새 버전 없음, 추출 생략」 규칙만 확정 |

## 00b에서 채택해 초안에 새로 넣은 것 (충돌 없음)

문서 단위 = 원천 문서 1건과 `source_doc_key` 일반화 · 금투협 수시공시를 문서 소스로 추가 · 파일 단위 원본파일 표(추출 상태는 파일 단위, 문서는 집계값) · `lineage_id`·`version_no`·`is_current`와 정정 판정 근거를 최초제출일 존재로 · 상품 표 `fund_type`(fndTp)·`product_class_code`(prdClsfCd)·`is_public_offering`·`valid_from`/`valid_to`(2단계 데이터 파이프라인 Flow 설계 예비) · short_code는 substring 파생 금지 · 매칭 실패 상태값 PENDING_MASTER / AMBIGUOUS / NO_CANDIDATE / NO_CODE_IN_SOURCE / BELOW_THRESHOLD / NORMALIZE_FAILED · 조인 키 3단(코드 → 정규화 펀드명 → 운용사명+설정일) · 수집 재시도는 타임아웃·5xx만 5회, 403은 즉시 알림 · 추출 상태값 EXTRACT_UNSUPPORTED_FORMAT / EXTRACT_PARTIAL / OCR_CANDIDATE / EXTRACT_NOT_APPLICABLE, 앞의 둘은 재시도 제외 · 워터마크 표 8소스 · 04에 위험등급 내생성과 자산군 보조 층화 축.

## 09-16 미팅 안건 (초안이 정할 수 없는 것)

1. finlife를 소스에서 빼는가, 금융회사 마스터(`fin_co_no`)·연금저축펀드 용도로 남기는가.
2. ELS 식별 키: 회차 번호 / KR6… 표준코드 / 일괄신고추가서류 단위 중 무엇으로 하는가.
3. 판매회사 명단 소스: PDF 본문 절 추출인가, 금투협 전자공시 수집인가.
4. 산출물별 3티켓 분할 여부(비고). 초안이 한 묶음으로 나왔으니 분할하지 않는 쪽을 권고.

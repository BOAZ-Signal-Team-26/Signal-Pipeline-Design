## 2. 검토 결과: 두 영역의 확장은 필요하지만 두 표로 고정할 수 없다

### R1. 문서·펀드 최종 점수와 백분위의 저장 계약이 아직 없다

`score.section_id`는 NOT NULL이고 유일키는 `(run_id, section_id, score_type)`이다. **PK는 score_id**다. 문서 순서·요약 비교 결과를 별도 관측값으로 저장하더라도, 이를 절 점수와 결합한 최종 문서/펀드 점수의 위치가 자동으로 정해지는 것은 아니다.

현재 `score.normalized_score`는 절 비교용이다. `fund_document` 모집단이 존재한다는 이유로 문서 백분위를 임의의 절 행에 넣을 수 없다. 문서 최종 결과를 뷰와 불변 manifest로 제공할지, 별도 결과 표로 제공할지 결정해야 한다. 문서/문서쌍 관측값 모델에 결과까지 담는다면 관측 단위·키·모집단 FK를 함께 설계해야 한다.

**닫을 조건:** metric_id/산식 버전, 계산 대상, 원자값→축값→최종값의 의존 관계, 집계·정규화 순서, 출력값·계산불가 사유의 저장 위치, fund_key/대표 파일/모집단 연결 승인.

### R2. “검증 결과 표 하나”는 평가 단위를 정하기 전의 가정이다

09-23 안건의 사람 트랙은 같은 유형 3쌍·총 18명·문서당 4문항·역균형 **제안**이다. LLM 트랙의 문항 수는 미정이다. 참고문헌의 12문항을 프로젝트 확정값으로 옮기지 않는다.

사람 응답은 참여자 × 문서 × 문항, LLM 응답은 평가 실행 × 문서 × 문항 × 문서 제공 조건 × 반복처럼 서로 다른 단위를 가진다. 문서쌍의 통계 요약은 그 위의 집계다. 최종 p값·총점만 남기면 원응답과 재채점 이력을 복원할 수 없다.

**최소 계약 후보:** 가명 참여자/모델 식별, 문서쌍·정확한 파일/구간, 문항·정답·채점기준 버전, 원응답과 채점값, 제시 순서, with/without-document 조건, 반복 ID, 모델/프롬프트/설정, 평가 대상 scoring run, 결측·중단 사유. 이들은 요구 후보이며 물리 표 수는 아직 정하지 않는다.

관계형 분리 저장과 평가 실행 + 불변 응답 manifest를 비교한다. SQL 조회 요구가 낮으면 파일 보존도 가능하므로 무조건 새 표 여러 개가 필요하다고 단정하지 않는다. 반대로 표 하나로 모든 입도를 합치는 것도 자동으로 적절하지 않다.

### R3. 추출 성공과 채점 가능성 사이의 상태 저장이 비어 있다

`score.raw_score`가 NOT NULL이므로 분모 0·적용 불가·입력 일부 실패 같은 **숫자가 없는 계산 결과**를 score_payload만 채운 행으로 남길 수 없다. 행을 만들지 않으면 미실행과 계산 불가를 구분할 별도 계약이 필요하다.

**대안:** 성공 점수만 score에 저장하고 시도/제외 사유를 실행 결과 manifest에 보존하거나, 결과 상태·nullable 원점수를 갖는 결과 모델을 설계한다. 0점 대입은 허용하지 않는다. 고지 판정은 충족/미충족/해당 없음/판정 불가를 분리하고, 적용 항목 수·평가 완료 수·분모 정책을 보존한다.

### R4. JSON 칸의 존재만으로 스키마 영향이 없어지는 것은 아니다

동일한 계산 단위·같은 출력 개수라면 배점·임계값·가중치 변경은 config/payload와 새 run으로 수용할 수 있다. 다만 다음은 기존 관계·키 재검토 조건이다.

- 같은 실행·절·점수유형에 여러 평가자/모델/정규화 결과를 동시에 저장.
- 축별 정규화마다 다른 학습/기준 집단을 사용. 한 개의 population FK만으로 충분한지 확인.
- 항목 하나가 여러 절/파일의 근거를 참조하거나 문서 전체의 부재를 판정.
- 문서/펀드 점수를 저장하고 드릴다운 근거까지 SQL로 질의.

payload에는 계약 버전, metric_id, 값·단위·분모·상태·근거를 정의한다. JSON에 ID를 넣는 방식의 참조 무결성은 DBML FK가 보장하지 않으므로 적재 검증 또는 관계형 분리가 필요하다.

### R5. canonical text만으로 표·페이지·시각적 구조가 보존되지는 않는다

원문 PDF 보존은 재추출을 가능하게 하지만, 평탄화된 텍스트와 char_start/end는 표 여부·페이지·좌표·시각적 강조를 보장하지 않는다. ASL의 표 제외나 표지 1페이지 이내 고지를 계산하려면 추출 산출물에 페이지·블록 종류·텍스트 구간 대응이 필요할 수 있다.

**닫을 조건:** 실제 채택한 지표의 입력 요구를 확인하고 구조 manifest 또는 블록/근거 관계를 선택한다. 같은 파일 속 요약–본문 구간쌍과 별도 파일쌍 모두 허용할지, 쌍의 방향·버전·중복 기준도 확정한다.

### R6. 축 4의 점수화 방향과 산출 가능한 상태를 구분한다

09-23 안건 2-3은 **고지 충실도를 점수로 추진**한다고 명시한다. 오래된 “필터로 고정”을 현행 방향으로 유지하지 않는다. 그러나 배점·분모·적용 상품군·법적 서류 대응·근거 절은 여전히 열려 있다. 점수라는 방향만으로 모든 문서에 숫자를 생성할 수는 없다.

문서 위치가 “제2부 10절(후보)”이면 후보로 보존한다. 점검표에 빈 항목이 있다는 이유로 미충족 판정하지 않는다. 기존 CDI/고지충실도 score_type을 유지할지, 합산 축과 별도 출력이 함께 필요한지도 최종 계약에서 정한다.

### R7. 경로·버전 계약은 수집 동결 전에 더 구체화해야 한다

09-22 결정의 상대경로와 자산 버전 기록은 이미 02·04·DBML에 있다. 원본 외 파생 텍스트·입력·모집단 manifest에도 같은 이식성 원칙이 필요하다. RAW_ROOT가 raw/의 상위 루트인지 raw/ 자체인지 정하지 않으면 raw/raw 중복 경로가 생길 수 있다(02에 기준 명시).

사전·감점표·프롬프트는 버전 이름만 남기지 말고 불변 파일 참조와 내용 해시를 함께 보존하는 계약을 제안한다. 같은 이름의 자산이 바뀌면 버전 문자열만으로 재현되지 않는다. LLM은 모델·설정·실제 응답을 남겨도 제공자 내부 변경에 따른 동일 출력까지 보장하지 않는다.

## 4. Notion 동기화에서 남은 오류

14개로 늘린 본문에도 아래 표현이 남아 있었다. 현재 로컬 정본과 다르거나 승인 수준을 과장한다.

- “DART 표지 XML + PDF라 2행”: 공개 표지는 HTML이고 API ZIP 내부는 미확인. 파일 수 고정 금지.
- “단축코드 5자리 하나=한 행”: 클래스 입도와 코드 유일성은 별개. 중복 후보 검증 필요.
- “score PK=(실행, 절, 점수유형)”: 실제 PK는 score_id, 앞 조합은 UNIQUE.
- “14→16개”, “7개 결정은 표 변경 없음”: R1~R5 조건에 따라 달라지는 추정.
- “09-22 물리화 완료”: DBML 논리 모델 반영이며 운영 DB 구축이 아니다.
- 파이프라인 티켓은 아직 9개 표를 입력으로 소개한다. 기존 회의 사실을 바꾸지 말고 현재 입력 버전을 덧붙이는 방식이 적절하다.

노션의 최신 본문·Mermaid 확인과 외부 대화형 ERD 아티팩트의 실제 갱신 검증은 별개다. 아티팩트를 열어 검사하지 않았으므로 갱신 완료라고 보고하지 않는다.

## 5. 미결 항목에 대한 권고 (승인 아님)

사용자가 확인해 준 사람·LLM 병행/사람 합친 안, 고지 충실도 점수화, 문서간 층내 백분위는 재논의하지 않는다. 현재 조회본의 미체크 박스는 10+7+7+8+4+3=**39개**이며 34개라는 요약과 다르다. 이미 방향이 정해진 항목도 체크가 남아 있으므로 39개를 독립 미결 결정 수라고 부르지 않는다.

|---|---|---|
| 검증 문서 선정 | 같은 상품유형·위험등급 안에서 우선 매칭. ETF 쌍이 안 되면 펀드로 파일럿을 한정하고 ETF 일반화 유보 | 표본 수를 맞추기 위해 상품 위험도와 설명 효과를 섞지 않음 |
| LLM 평가 조건·담당 | with/without-document 대조를 파일럿으로 먼저 검증. 다빈이 평가 설계·분석, 민석이 문항·정답·채점안 담당하는 안을 제안 | 문항 수·담당·일정은 팀 승인 필요. 독립 세션과 동일 문항, 입력 누락/잘림 확인, 모델·프롬프트·채점기준·반복 기록. 차이 작음은 사전지식의 천장효과일 수 있어 곧바로 나쁜 문서 판정 금지 |

| 두 번째 용어 변수·사전 | 설명 없는 첫 등장을 후보로 파일럿하고 Common words는 말뭉치 확보 뒤 재검토. 한국은행 700선 기반에 문서 내 용어·검수된 펀드 용어 보완 | “첫 등장” 범위와 앞선 정의/근접 설명 인정 규칙 미확정이면 후보값만 산출. 사전 미등재를 쉬운 단어로 단정 금지 |
| 용어 깊이 | 사전만 사용으로 v0 범위를 닫고 정의 연결은 소규모 조사, 정식 온톨로지는 보류 | 기능·입력 단위가 달라지므로 JSON 자리만으로 비용을 흡수한다고 판단하지 않음 |
| 정의어 2회 이하 | 확정 감점 기준 대신 검토 플래그로 사용 | 표본 1건이며 정의문 자체·목차·머리말 제외 규칙 필요. 회의록의 빈도표는 7+0+6+3=16인데 총 17개로 적혀 있어 한 용어 누락/분류를 먼저 대조 |
| 상호참조 | 유형·대상·원문 구간을 수집하고 길이당 빈도와 참조 의존도를 함께 검토 | 문서 안/다른 서류라는 이유만으로 일괄 감점 금지. “상기·전술·위의”는 추출 후보로 추가하되 동일 구간의 중복 탐지 제거 |
| 구조 시각성·요약 비교 | 시각 구분은 사람 검토 후보로 보류. 요약 비교는 핵심 위험·비용 정보의 보존 여부와 불필요한 반복을 나눠 파일럿 | 임베딩 유사도 높음만으로 요약 실패 판정 금지. 적절한 요약도 본문과 유사함 |

| 축 4 분모·결측 | 해당 상품·서류에 적용되는 검증된 항목을 분모로 사용하고 평가 완료율을 별도 표시 | 미완성 항목·추출 실패를 X로 채우거나 조용히 분모에서 빼지 않음. 미평가가 있는 최종 점수의 공개/보류 규칙 필요 |

| 축 방향·축간 정규화 | 충실도 원값이 [0,1] 충족률이면 1−충족률 후보. 고정 기준집단에서 축별 [0,1] 변환 후 잠정 1/4 가중 | 감점 합산 값이면 같은 변환을 그대로 쓰지 않음. 기준집단·변환 파라미터·동점/상수축 처리 고정. 최종 층내 백분위와 분리. ASL은 평균이므로 정수가 아닌 소수 가능 |

주영의 09-26 초안을 위해서는 저장 위치뿐 아니라 **계산 단위·필수 입력·적용/결측 상태·분모**가 먼저 필요하다. 다른 결정이 모두 다빈 내부에서 끝난다는 설명은 정확하지 않다. 최종 배점은 버전으로 바꿀 수 있지만 입력 단위가 달라지면 수집·추출·인계 계약도 달라진다.

## 6. 검증

이번 변경은 검토 기록·정책·DBML 주석 중심이며 14개 표의 칼럼·키·관계를 임의 확정하거나 추가하지 않았다.

- @dbml/core 파싱 성공: 14개 표, 31개 관계. HEAD와 비교한 칼럼·타입·PK/NOT NULL/UNIQUE 속성 동일.
- DBML과 Mermaid의 부모→자식 관계 목록(중복 포함) 일치.
- 변경 Markdown 및 본 문서의 상대 파일 링크 24개 존재 확인, git diff --check 통과.
- 실제 DB 적용·CDI 계산·외부 대화형 ERD 렌더링 검증은 수행하지 않았다. Notion은 조회·대조했으며 이 작업에서 원문을 수정하지 않았다.

# 16. 소스별 데이터 현황표 (7항목 × 문서 4종)

「데이터 가져온거 보고 분석해보기」 티켓(정담당 주영 / 부담당 대현, 마감 09-14)의 산출물이다.
09-20에 대현이 작성했다. **완료 체크는 하지 않았다** — 조건 3(샘플 머지)·4(싱크 공유)는 주영 몫이다.

`15`가 「어떻게 받아오나」라면 이 문서는 **「받아보니 무엇이 들어 있나」**다.
값의 성질만 적고, 그것으로 무엇을 할지는 `01`·`03`·`05`가 갖는다.

## 결론 먼저

| 물음 | 답 |
|---|---|
| 7항목을 4종 모두 채웠는가 | **아니다.** 제재공시 **5칸**이 「모름」이다 (연초누적·결측·값표기·이상값·증분필터). 판매사 표기와 상품명은 스펙으로 해소됐다 |
| 가장 큰 발견 | ~~「전수」가 금투협에 성립하지 않는다~~ → **철회 (09-20 실측).** 제약은 한 요청의 기간 폭이지 소급 한계가 아니다. 2년 전 구간도 조회된다. **측정 불가가 아니라 미측정이다** |
| 표 구조를 바꿀 문제 | **2건** (8절). 09-20 금투협 실측으로 한 건이 소멸했다. 둘 다 「무엇을 분모로 세는가」 문제다 |
| 09-14에 「모름」이던 판매사 표기 | **해소.** 소스 셋이 각각 다르게 준다(4절) |

## 0. 읽는 법 — 이 표의 4종은 「문서 단위」다

`00b` 3절이 정한 대로, 전수와 결측률을 같은 표에 놓을 수 있는 것은
**DART 펀드공시 · 제재공시 · 분쟁조정결정례 · 금투협 수시공시** 넷뿐이다.
행 하나가 「공시 문서 1건」이고 발행일·발행 주체·본문·첨부가 공통이다.

**finlife · KRX · 공공데이터포털은 이 표에 넣지 않는다.** 결측의 뜻이 다르기 때문이다.

| | 결측의 뜻 |
|---|---|
| 문서 4종 | 「문서에 첨부가 없다」 |
| API 3종 | 「필드 값이 비어 있다」 |

**기간 창은 통일하지 않는다 (09-14 결정).** 최근 90일로 자르면 분쟁조정이 사실상 0건이 되는데,
분쟁조정은 골든셋 라벨이라 누적 전체를 봐야 한다.

## 1. 전수

| 소스 | 행 단위 | 누적 전수 | 2026 연초 누적 | 조회 기준일 |
|---|---|---|---|---|
| DART 펀드공시 | 접수번호 | — | **2,337건** (90일 창) | 2026-09-14 |
| 제재공시 | 제재정보번호 | **5,735건** (2000년 이후) | 모름 | 2026-09-14 |
| 분쟁조정결정례 | 게시글(사건) | **814건** (금융투자 **187건**) | — | 2026-09-14 |
| 금투협 수시공시 | **조회 행 = 클래스 단위** | **미측정** (아래) | 미측정 | — |

**금투협의 누적 전수는 「미측정」이다 (09-20 정정).** 초판은 「조회 창이 1년이라 물을 수 없다 =
측정 불가」로 적었으나 **틀렸다.** 제약은 한 요청의 기간 폭이지 소급 한계가 아니어서,
**1년 미만 창으로 쪼개면 얼마든지 셀 수 있다**(`15` 1-1절 실측). 아직 세지 않았을 뿐이다.

참고로 11개월 한 창이 **225,177행**이다. 백필 분량을 이제 산출할 수 있다.

대신 3일치 표본으로 밀도를 잰다 — **2026-08-13~15, 1,499행 / 자연키 묶음 882건 / 운용사 25곳.**
행이 아니라 문서로 세면 사흘에 882건이다(`reference/kofia_ann_sample.csv`).

**DART 6,473건은 쓰지 않는다.** 기간 창이 불명확한 추정치다(`00b` 2절). 90일 창 2,337건만 쓴다.

## 2. 필수 칸 결측

**「수수료」는 결측률 대상에서 뺀다 (09-14 결정).** 어느 API에도 수수료 필드가 없다.
투자설명서 본문에서 뽑는 값이다.

| 소스 | 결측 실측 |
|---|---|
| DART 펀드공시 | 표본 10건 기준 — 펀드코드 **10/10 있음**, 위험등급 **10/10 있음**, **판매회사 명단 0/10** |
| 제재공시 | **모름** — 인증키 미발급. 응답을 한 번도 받지 못했다 |
| 분쟁조정결정례 | 본문 추출 실패가 결측이다. 첨부 213단위 중 **HWP 3.0 94건 · 배포용 7건** |
| 금투협 수시공시 | 표본 1,499행에서 **파싱 대상 13칸 전부 결측 0.00%** |

**DART의 판매회사 명단 0/10은 누락이 아니라 구조적 부재다.** 표지에 「각 판매회사 본·지점」
안내 문구만 있고 명단이 없다(`09`). 판매사는 금투협에서 받는다(`14` 4절).

## 3. 값 표기 방식

| 소스 | 실측된 표기 |
|---|---|
| DART 펀드공시 | 위험등급이 **`2등급[높은 위험]` / `2등급[ 높은 위험 ]` / `2등급[높은 위험 ]`** — 표본 10건 안에서 **공백 변형 3종**. 1~6등급이며 **1등급이 최고위험** |
| 제재공시 | **모름.** 단 스펙상 날짜가 **3종**이다 — 요청 `YYYY-MM-DD` / `actReqDate` `2026.04.24` / `inputDate` `2026-04-27 10:14:12` |
| 분쟁조정결정례 | 해당 없음 (위험등급·수수료 같은 정형 값이 없는 서술형 문서) |
| 금투협 수시공시 | `standardCd` 접두가 **3종** — `K55` 887 / `KR5` 603 / `KRM` 9. **한 칸에 두 코드 체계가 섞인다**(`12`). PDF 본문의 위험등급은 `투자 위험등급 N등급[명칭]` |

**공백 변형은 정규식으로 흡수해야 한다.** `「(\d)등급`만 보고 뒤를 버리는 것이 안전하다.

## 4. 판매사 이름 표기 — 09-14의 「모름」 해소

소스 셋이 **각각 다르게** 준다. 하나로 합치려면 정규화가 필요하다(`05` 9절).

| 소스 | 표기 | 예 |
|---|---|---|
| 금투협 판매회사 마스터 | 한글 법인명 + **판매사코드** | 200곳. **코드가 있어 문자열 매칭이 필요 없다**(`14` 4절) |
| 제재공시 `finInstName` | **법인격 없는 약칭** | `교통은행` (`14` 6절) |
| 분쟁조정결정문 | **마스킹** | `●●증권` · `○○○○○○ 주식회사` (`14` 5절) |
| DART 표지 | **없음** | 안내 문구만 |

**운용사 쪽은 구 상호가 함정이다.** 536건 중 97건(18%)이 구 상호를 갖고, 그중 44건은
업종 접미사까지 바뀐다(`누림투자자문` → `누림자산운용`). 유사도로는 잡히지 않는다
(`reference/kofia_mgmt_codes.csv`의 `former_name`).

## 5. 상품명 표기

| 소스 | 표기 |
|---|---|
| DART 펀드공시 | 정식 명칭. `미래에셋밸런스롱숏증권자투자신탁1호(채권혼합)` — **호수를 `1호`로** |
| 금투협 수시공시 | `미래에셋밸런스롱숏증권자투자신탁 1(채권혼합)` — **공백 + `1`**. 클래스 행은 `└▶` 접두 |
| KRX (참고) | **상장 약명** `1Q 200액티브` ↔ 정식 `하나1Q200액티브증권상장지수투자신탁[주식]` |
| 분쟁조정결정례 | **마스킹** `▣▣ ▤▤▤▤▤ 아시아 무역금융 전문투자형 사모투자신탁1호` — 고유명만 가림 |
| 제재공시 | **마스킹** `㉮펀드` |

**펀드명은 조인 키로 부적합이 확정됐다.** DART와 금투협의 공백·호수 표기가 다르고,
KRX는 이름 공간 자체가 달라 완전일치가 **0.0%**다(`13` 4절).

## 6. 이상값

| 소스 | 이상값 |
|---|---|
| DART 펀드공시 | 「[ 본 문 ]」 요소가 **PDF 링크 한 줄**이다(10/10). 본문이 토막 온 것이 아니라 원래 그렇다 |
| 제재공시 | **모름.** 스펙상 본문이 `㉮펀드`·`甲`·`A지점`·`㈜C`로 마스킹된다는 것만 안다 |
| 분쟁조정결정례 | HWP 3.0 **94건**(1999~2004), 배포용 **7건**, BMP 내장 **4건**(스캔본 아님. `PrvText`로 약 1,022자 부분 복구) |
| 금투협 수시공시 | **`tmpV1`의 `ZZZZZZ…` 33건은 결측이 아니라 모펀드 행 표시자다**(`12`). 지우면 자연키가 깨진다. 그리고 `urllib`로 받으면 **응답이 잘린다**(1,499행 → 43행) |

## 7. 기간 분포와 증분 축

| 소스 | 데이터 기간 | 증분에 쓸 날짜 칸 |
|---|---|---|
| DART 펀드공시 | 90일 창 실측 | `rcept_dt` |
| 제재공시 | 2000년 이후 누적 | `actReqDate` 또는 `inputDate` — **둘 중 어디에 필터가 걸리는지 모름** (`15` 10절) |
| 분쟁조정결정례 | 누적 전체. 추출 성공 112건 중 **2015년 이후 52건(46.4%)** | 게시글 번호 |
| 금투협 수시공시 | **최근 1년만** | `standardDt` |

**분쟁조정의 연도 분포는 데이터가 아니라 파서의 한계다.** HWP 5.0 채택 시점 때문에
최근 문서일수록 추출에 성공한다. **연도별 비교 분석은 HWP 3.0 파서가 생기기 전까지 유보한다**(`00b` 5절).

## 8. 표 구조를 바꿀 문제 — 2건

티켓 완료 조건 2번이 요구한 「3건 이하」다. 둘 다 **「무엇을 분모로 세는가」** 문제다.

**초판은 3건이었다.** 「「전수」 칸이 모든 소스에 성립하지 않는다」를 문제 1로 들었는데, 그 근거였던
「금투협은 조회 창이 1년이라 누적 전수가 없다」가 09-20 실측으로 무너져 **소멸했다**(1절).

### 문제 1. 분쟁조정은 분모가 셋이다

**사건 814건 / 금융투자 187건 / 첨부 845개**가 모두 다른 분모다.
「추출 성공 112건」은 **첨부 213단위** 기준이고 사건 187건이 아니다.
결측률을 적는 칸에 **분모를 함께 적는 칸**이 없으면 이 숫자들은 반드시 섞인다.

### 문제 2. 「결측」이 두 가지 뜻으로 쓰인다

문서 4종에서는 「첨부가 없다」, API 3종에서는 「필드가 비었다」다.
`01`의 원본파일 표와 상품 표가 각각 다른 뜻의 결측을 담는데 **칸 이름이 같다.**
`03`의 실패 상태값처럼 **원인을 구분하는 값**이 결측에도 필요하다.

## 9. 「모름」과 그 이유

티켓 규칙이 「모르면 모름이라 적고 이유를 1줄 단다」이므로 그대로 따른다.

| 항목 | 이유 |
|---|---|
| 제재공시의 2·3·6항목 (결측·값 표기·이상값) | **인증키 미발급.** 응답을 한 번도 받지 못했다. `--probe` 한 번이면 닫힌다 |
| 금투협 누적 전수 | **미측정.** 측정 가능하다(1절). 1년 미만 창으로 쪼개 세면 된다 |
| 제재공시 2026 연초 누적 | 같음 |
| 제재공시 증분 필터 대상 필드 | 같음 (`15` 10절 미확인 2) |
| 금투협 2026 연초 누적 | 조회 창 1년 안에 들어오므로 받을 수는 있으나, **아직 받지 않았다** |
| DART 연초 누적 6,473건의 기준 기간 | `00b`가 추정으로 표시. 확정 안 됨 |

**「측정 불가」로 분류할 항목은 이제 없다 (09-20).** 금투협 누적 전수가 유일한 후보였는데
측정 가능한 것으로 확인됐다.

## 10. 재현

```bash
python3 scripts/fetch_kofia_ann.py 20260813 20260815 | python3 scripts/parse_kofia_ann.py
```

1절·2절·3절·6절의 금투협 수치가 그대로 나온다.
`reference/kofia_ann_sample.csv`(1,499행)가 같은 조회의 결과물이다.

**분쟁조정은 09-20에 수집 경로를 복구했다** — `scripts/fetch_fss_dispute.py`.
`nttId` 8건에서 역추적했고, 받아서 본문까지 뽑아 마스킹을 재현했다.

**저장소에 아직 없는 샘플**: DART 펀드공시 · 제재공시.
DART는 받은 적이 있으나 CSV로 남기지 않았고, 제재공시는 키가 없다.

**2절의 분쟁조정 결측을 이제 다시 잴 수 있다.** 지금 적힌 「첨부 213단위 중 HWP 3.0 94건」은
팀의 09-05 기록을 옮긴 것이고 이 저장소의 실측이 아니다. 경로가 생겼으므로 재측정이 가능하다.

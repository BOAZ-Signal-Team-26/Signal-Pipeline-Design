# 05. 상품 매칭 임계치와 「상품 못 찾음」 규칙

작성 09-14, data-scientist. [[00_context_brief.md]] 전제 그대로 따름. 실제 데이터 없음 — 수치는 전부 잠정값.

## 1. 정규화 단계 (순서대로)

문서 표의 상품명 문자열을 상품 표에 맞추기 전에 아래 순서로 정규화한다. 순서가 중요한 이유는 뒤 단계가 앞 단계의 결과에 의존하기 때문이다.

| 순서 | 단계 | 잡는 실패 사례 |
|---|---|---|
| 1 | NFKC 정규화 | "Ａ형" vs "A형", 전각 숫자·괄호 vs 반각 같은 호환 문자 차이 미매칭 |
| 2 | 공백 전면 제거 | "삼성 그룹주 펀드" vs "삼성그룹주펀드" 같은 공백 개수·위치 차이 미매칭 |
| 3 | (주)·주식회사 표기 제거 | 운용사 법인 표기 유무 차이("(주)미래에셋자산운용" vs "미래에셋") 미매칭 |
| 4 | 유형 괄호(「[주식-파생형]」 등)·호수(「제1호」, 「1호」, 「 1」)·클래스 표기(A형, C-e형, Ce, ClassA)를 각각 별도 필드로 분리 | 본체명에서 부가 정보를 떼어내지 않으면, 유형·호수·클래스만 다른 별개 상품이 같은 상품으로 오매칭되거나, 반대로 부가 표기 차이 때문에 같은 상품이 다른 상품으로 오분류된다. 분리된 호수 필드는 3절 하드 룰에서, 클래스 필드는 매칭 이후 상품 계열 내 클래스 판정에서 쓴다 |

**(00b 반영)** 정규화 순서를 NFKC → 공백 전면 제거 → (주)·주식회사 제거 → 유형 괄호·호수·클래스 분리로 재구성했다. 기존 표의 「전각/반각 변환」은 NFKC 정규화가 포괄하므로 별도 단계로 남기지 않는다. 「상장지수」 부분 문자열 검사는 서로 다른 문자열을 같게 만드는 정규화가 아니라 ETF인지 아닌지를 가르는 판정 규칙이므로, 2절로 분리해 옮긴다.

## 2. ETF 판정 규칙

**(00b 반영)** 신규 절. 기존 정규화 표 6단계에 있던 「상장지수」 문자열 검사를 분리한 것이다.

**규칙**: 정규화된 상품명에 「상장지수」 문자열이 위치와 무관하게 포함되면 ETF로 판정한다(09-09 확정).

**근거**: 이 검사는 서로 다른 상품명을 같은 문자열로 만드는 정규화가 아니라, 정규화가 끝난 문자열 하나를 보고 상품군을 분류하는 별개의 판정 규칙이다. 정규화 단계 표에 남겨두면 「정규화 = 매칭 전처리」라는 1절의 성격과 어긋난다.

**검증 예정**: 00b A7이 09-15 실측으로 이 규칙의 오분류율(KRX ETF 1,167건과 공공데이터포털 「상장지수」 포함 집합 대조)을 확인할 예정이다. 누락·오탐 각 1% 미만이면 규칙 유지, 오탐이 유의미하면 KRX 대조를 1차 판정으로 승격한다는 것이 00b의 권고다. 실측 결과는 이 문서 작성 시점에 아직 반영되지 않았다. **미확인**.

## 3. 하드 룰: 유사도 점수와 무관하게 탈락시키는 조건

**(00b 반영)** 신규 절. 유사도 점수가 아무리 높아도 특정 필드가 다르면 자동으로 매칭을 탈락시키는 규칙 두 가지를 정의한다.

**(a) 모자 구분 (`is_feeder`)**

**결정**: 상품명에서 「증권투자신탁」(모)과 「증권자투자신탁」(자)의 구분을 별도 필드(가칭 `is_feeder`)로 추출한다. 문서 쪽과 상품 쪽의 `is_feeder` 값이 다르면 유사도 점수와 무관하게 탈락시킨다.

**근거**: 「자」 한 글자는 표기 오차가 아니라 모펀드와 자펀드라는 서로 다른 상품을 가리키는 결정적 정보다. 토큰 유사도 계열 방법은 문자열 대부분이 같으면 높은 점수를 주므로, 이 한 글자 차이를 사소하게 취급해 서로 다른 상품을 매칭시킬 위험이 있다. 점수 기반 판단이 구조적으로 놓치는 사례이므로, 점수 계산과 별개로 필드를 뽑아 규칙으로 가른다. **(아키텍트 판정, 채택)** 09 실측([[09_verify_dart_cover.md]])에서 확보한 10건 자체에 모·자 두 표기가 실제로 섞여 있었다 — 예: 「신한미국나스닥100인덱스증권자투자신탁」·「카디안 월지급아시아퍼시픽고배당증권자투자신탁」·「카디안 미국뱅크론특별자산자투자신탁」은 「자」가 있는 자펀드 표기이고, 「신한일반채권증권투자신탁제1호」는 「자」가 없는 모펀드 표기다. 가상 사례가 아니라 실측 10건 안에서 이미 관측된 구분이므로 하드 룰의 필요성이 실증된다.

**(b) 호수 일치**

**결정**: 1절 4단계에서 분리한 호수 필드가 문서 쪽과 상품 쪽에서 다르면, 유사도 점수와 무관하게 탈락시킨다.

**근거**: 모자 구분과 같은 이유다. "OO펀드제1호"와 "OO펀드제2호"는 본체명이 거의 같아 토큰 유사도가 높게 나오지만 실제로는 다른 상품이다.

**(c) 기존 「숫자 토큰 완전 일치」 규칙(4절)과의 관계**

**결정**: (b)에 완전히 흡수되지 않는다. 기존 규칙은 호수뿐 아니라 "코스피200" 같은 지수·기초자산 숫자를 포함한 모든 숫자 토큰의 완전 일치를 요구하는 일반 규칙이었다. 호수는 이제 별도 필드로 분리되어 (b)의 전용 하드 룰로 더 정확하게 처리되지만, 호수가 아닌 숫자 토큰(지수명 등)은 여전히 4절의 일반 규칙으로 걸러야 한다. 따라서 4절 규칙은 범위를 「호수를 제외한 숫자 토큰」으로 좁혀 유지한다.

## 4. 유사도 방법

**결정**: 편집 거리 계열보다 **토큰(부분 문자열 집합) 계열 유사도**를 주 방법으로 쓴다. 단 숫자 토큰(200, 2호 등)은 유사도 점수와 무관하게 완전 일치를 강제하는 규칙을 덧붙인다.

**근거**: 한국어 상품명은 짧고, 숫자·영문이 섞이며, 어순이 문서마다 조금씩 다를 수 있다("삼성 코스피 200 인덱스" vs "삼성코스피200인덱스펀드"). 어순에 민감한 편집 거리보다 토큰 집합 기반 유사도가 어순 변화에 강하다. 다만 토큰 유사도는 숫자 한 글자 차이(1호 vs 2호)를 사소한 차이로 오인하기 쉬우므로, 숫자 토큰만은 정확히 일치해야 매칭을 허용하는 예외 규칙으로 보완한다. 라이브러리·알고리즘 이름은 여기서 정하지 않는다.

**(00b 반영)** 위 숫자 토큰 완전 일치 규칙은 호수를 제외한 숫자 토큰(지수명 등)에 한정한다. 호수는 3절 하드 룰 (b)에서 유사도 점수 계산과 무관하게 별도로 처리한다.

## 5. 임계치 잠정값과 비용 비대칭

**(아키텍트 판정)** 00b가 제안했던 소스 성격별 두 벌 임계치 체계는 기각한다. 기존 단일 표(0.85 자동매칭 / 0.60~0.85 수동 확인 / 0.60 미만 실패)를 유지하고, 대신 이 표가 적용되는 범위를 명시한다.

**결정(잠정값)**:

| 유사도 구간 | 처리 |
|---|---|
| 0.85 이상 | 자동 매칭 |
| 0.60 ~ 0.85 | 매칭 후보로 남겨 사람이 확인 (라벨 대상) |
| 0.60 미만 | 매칭 실패로 분류 |

**적용 범위 (아키텍트 판정)**: 코드가 있는 소스(DART·금투협·공공데이터포털)에서 문자열 매칭은 1차 수단이 아니라, 코드 조인(short_code 등, [[01_logical_schema.md]] 사안)이 실패하거나 코드 자체가 없는 **잔여 건에만 적용되는 2차 수단**이다. 위 표는 그 잔여 건에 적용된다. 09 실측([[09_verify_dart_cover.md]])에서 DART 투자설명서 표지의 펀드코드가 확보한 10건 전부(10/10)에 존재했으므로, 코드 조인 실패 잔여 건은 소량이고 어차피 사람이 보는 규모다. 00b가 제안했던 「코드 있는 소스 전용, 0.80 미만만 제외하는 재현율 우선 벌」은 이 표의 0.60~0.85 수동 확인 구간과 기능이 겹쳐 기각한다. 코드가 영원히 없는 소스(분쟁조정·제재공시)의 확정 규칙은 이 표와 별개로 6절에 둔다.

**근거(비용 비대칭)**: 임계치를 낮추면 과매칭이 늘어난다 — 다른 상품의 위험등급이 잘못 붙어 CDI 정규화 모집단이 조용히 오염되고, 겉으로는 실패처럼 보이지 않아 발견이 늦다. 임계치를 높이면 미매칭이 늘어 표본이 줄고 특정 상품군·판매사에 편향([[04_score_storage_and_population.md]] 3-3절)될 수 있지만, 미매칭은 행 단위 로그로 눈에 보이므로 사후 발견·보정이 가능하다. 따라서 과매칭 비용이 미매칭 비용보다 크다고 보고, 임계치는 보수적으로(자동 매칭 문턱을 높게) 잡고 애매한 구간은 사람 검증을 거치게 한다.

**판매사 이름 별도 임계치**: 필요하다. 판매사명은 상품명보다 문자열이 짧고 반복도가 높아("OO증권", "OO은행") 상품명용 임계치를 그대로 적용하면 우연히 높은 점수가 나와 과매칭될 위험이 크다. 잠정값은 **0.95 이상**으로 상향한다(아키텍트 판정, 기존 0.90에서 조정 — 6절 분쟁·제재 확정 규칙에 쓰이는 값과 통일). 사업자번호 등 코드성 식별자가 있으면 그것을 우선 사용한다.

## 6. 코드가 영원히 없는 소스의 자동 확정 규칙 (분쟁조정·제재공시)

**결정 (아키텍트 판정, 채택)**:

| 조건 | 처리 |
|---|---|
| 판매사명 유사도 0.95 이상 **AND** 단독 후보 **AND** 교차 확인(제재조치일·문서 내 다른 식별 정보 일치) | 자동 확정 |
| 그 외 | 수동 확인 |

분쟁조정 187건은 전건 수동 확인을 권고한다(00b A3·A8, 아키텍트 판정으로도 유지). 규모가 작아(187건) 전건 수동이 실행 가능하다.

**근거**: 분쟁조정 결정문은 상품명이 전부 마스킹되어 있어([[00_context_brief.md]]) 애초에 상품명 유사도로 매칭할 대상이 없다. 연결은 판매사 축(또는 별도 축)으로만 이루어진다([[00_context_brief.md]] 5번). 따라서 이 확정 규칙은 5절의 상품명 유사도 표와는 완전히 별개 축(판매사명)이다. 코드도 없고 상품명도 없는 이 소스에서 자동 확정에 이르는 유일한 경로이므로 정밀도를 최우선으로 삼아 판매사명 유사도·단독 후보·문서 내 교차 확인을 모두 요구해 오매칭 여지를 최소화한다.

## 7. 라벨 200건 표본 요건

**(00b 반영, 아키텍트 판정 반영)** 라벨 대상은 「코드 있는 소스의 문자열 잔여 건(코드 조인 실패분, 5절 표 적용 대상) + 분쟁·제재 187건(6절 확정 규칙 적용 대상)」이다.

- **층화 기준**: 분쟁·제재 187건을 전건 수동 확인하면, 라벨 200건 표본의 대부분(187건)이 이미 분쟁·제재로 채워진다. 나머지 소수(200에서 187을 뺀 13건 안팎)는 코드 있는 소스의 문자열 잔여 건 중 5절 표의 0.60~0.85 애매 구간을 중심으로 층화 추출한다.
- **ETF·특정 판매사 과소 표집 방지**: 상품군·판매사별 최소 할당 건수를 두는 층화 추출을 쓴다(N 잠정값은 현황표 확보 후 정함).
- **코드 있는 소스의 잔여 건 규모는 미확인이다.** 코드 조인 실측(조인 대조표, 09-16) 이후에만 잔여 건수·분포를 알 수 있으므로, 세부 층화 기준은 그 실측 이후로 미룬다.
- **임계치 확정 절차**: 라벨 200건에 대해 사람이 매칭/비매칭 정답을 표시 → 5절 표(상품명 유사도)와 6절 규칙(판매사명 유사도)을 각각 그 성격에 맞는 표본 부분집합으로 따로 검증 → 비용 비대칭(과매칭 비용 > 미매칭 비용)을 반영해 재현율보다 정밀도를 우선하는 값을 최종 채택한다.

| 신규 코드 | 상태·의미 | 재처리 |
|---|---|---|
| PENDING_MASTER | 매칭 대상 상품 마스터가 아직 도착하지 않음. 정상 상태 | 30일 재시도 |
| AMBIGUOUS | 다중 후보 동점, 또는 코드 없는 소스에서 6절 자동 확정 조건을 충족하지 못해 사람이 봐야 함 | 수동 큐 |
| NO_CANDIDATE | 후보 자체가 없음(상품 표에 대응 상품 없음 — 신규상품, 상장폐지 등) | 주 1회 재시도 |
| NO_CODE_IN_SOURCE | 소스 구조상 코드를 영원히 이어 붙일 수 없음(분쟁조정·제재공시. 상품명 자체가 마스킹되어 판매사 축으로만 연결) | 재시도 대상 아님(구조적) |
| BELOW_THRESHOLD | 유사도가 최소 문턱 미만 — 코드 있는 소스 잔여 건은 상품명 유사도 0.60 미만(5절), 코드 없는 소스는 판매사명 유사도 0.95 미만이거나 단독 후보·교차 확인 조건 미충족(6절) | 재시도 대상 아님(정규화 개선 시 재평가) |
| NORMALIZE_FAILED | 원문이 파싱 단계에서 깨져 정규화 자체가 불가 | [[03_failure_policy_collect_parse.md]] 본문 추출 실패와 연계 |

**구 분류(A~D)와의 대응**:

| 구 코드 | 신 코드 | 비고 |
|---|---|---|
| (해당 없음) | PENDING_MASTER | 구 분류에 없던 상태. 매칭 시도 이전에 마스터 데이터가 아직 없는 정상 대기이며, 실패가 아니다. 근거: DART가 금투협·공공데이터포털보다 6~18일 선행해서 들어오므로, DART 문서가 먼저 도착한 시점에는 아직 상품 마스터가 없는 것이 정상이다(00b A2·A5) |
| A. 임계치 미달 | BELOW_THRESHOLD | 코드 있는 소스 잔여 건은 상품명 유사도 0.60 미만(5절), 코드 없는 소스는 판매사명 유사도 0.95 미만 또는 단독 후보·교차 확인 조건 미충족(6절)이 이 코드에 해당 |
| B. 후보 없음 | NO_CANDIDATE / NO_CODE_IN_SOURCE로 분리 | 신규상품·상장폐지처럼 정말 후보가 없는 경우는 NO_CANDIDATE, 분쟁·제재처럼 소스 구조상 애초에 코드·상품명이 없는 경우는 NO_CODE_IN_SOURCE로 원인을 구분한다 |
| C. 다중 후보 동점 | AMBIGUOUS | 코드 없는 소스에서 단독 후보 조건을 충족하지 못하는 경우도 이 코드로 흡수 |
| D. 정규화 실패 | NORMALIZE_FAILED | 동일 |

이 분류는 초안이며, 실제 실패 사례를 현황표(09-14)·조인 대조표(09-16)에서 본 뒤 세분화한다. **미확인**.

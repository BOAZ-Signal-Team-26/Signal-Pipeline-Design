# 15. 데이터 소스 API 명세 (엔지니어링 참조)

**이 문서의 범위는 「어떻게 호출해서 받아오는가」 하나다.** 받은 뒤의 일 — 원본 보관은 `02`,
수집·파싱 실패 판정은 `03`, 조인 키는 `01`, 각 사실의 실측 근거는 `09`·`10`·`12`·`13`·`14`에 있다.
같은 내용을 여기에 다시 쓰지 않는다. 두 벌이 되면 반드시 어긋난다.

작성 2026-09-20. 모든 파라미터는 **실측 또는 공식 스펙 페이지 판독**으로 확인한 것이며,
확인하지 못한 것은 절마다 「미확인」으로 표시했다.

**이 문서는 `12`~`14` 같은 실측 기록이 아니라 현행 명세다.** 소스가 바뀌면 실측일을 덧붙이지 말고
이 파일을 고친다. 기록은 기록대로 그 자리에 둔다.

### 무엇을 어디에 적는가

| 사실 유형 | 소유 파일 |
|---|---|
| 엔드포인트 · 요청 전문 · 파라미터 · 인증 · 페이징 · 응답 구조 · 호출 함정 | **15 (이 문서)** |
| 호출 간격 · 타임아웃 · 재시도 횟수의 구현값 | **15 (9절)** — 스크립트 주석은 여기를 가리킨다 |
| 실패 판정 기준 · 상태값 · 재시도 정책 · 격리 · **워터마크 룩백 일수** | `03` |
| 원본 경로 · 파일명 · 버전 · 메타데이터 · **중복 판정 정책** | `02` |
| 자연키 · 조인 판정 · 스키마 칸 | `01` |
| 실측 수치와 그로 인한 판정 | `09` · `10` · `12` · `13` · `14` |

경계는 **「요청·응답이 어떤 형태인가」는 15, 「그 형태로 무엇을 할지」는 기존 문서**다.
15는 「증분에 쓸 수 있는 요청 변수가 무엇인가」까지 쓰고, 「룩백 며칠」은 `03`이 갖는다.

**「공식 명세」 열이 이 표의 핵심이다.** 명세가 없는 소스는 우리가 읽어 낸 것이 전부이므로,
서버가 말없이 바뀌면 알 방법이 없다. 금투협·KRX·DART가 여기 해당한다.

**세 가지를 먼저 알아야 한다.**

1. **`urllib`로는 금투협을 받을 수 없다.** 응답이 중간에서 잘린다(1,499행 중 43행). `curl`을 쓴다.
2. **파라미터 누락이 오류가 아니라 「빈 결과」로 나타나는 소스가 있다.** 금투협 `uRptAllYN`이 대표적이다.
   HTTP 200 + 정상 XML + 0행이 온다. 0건을 정상으로 넘기면 안 된다(`03`).
3. **금감원 OPEN API의 JSON 루트 키는 `reponse`다.** `response`가 아니다. 공식 스펙의 오타이며
   그대로 따라야 한다.

## 1. 금투협 전자공시 (dis.kofia.or.kr) — 인증 불필요

화면이 WebSquare이고 뒤에 **proframe**이라는 XML-RPC 계열 서버가 있다. 공식 API 문서는 없다.
아래는 화면 JS를 읽고 실호출로 확인한 것이다(`12`).

### 공통 호출 형식

```
POST https://dis.kofia.or.kr/proframeWeb/XMLSERVICES/
Content-Type: text/xml; charset=UTF-8
Referer: https://dis.kofia.or.kr/websquare/index.jsp
```

```xml
<message>
  <proframeHeader>
    <pfmAppName>FS-DIS2</pfmAppName>
    <pfmSvcName>{서비스명}</pfmSvcName>
    <pfmFnName>{함수명}</pfmFnName>
  </proframeHeader>
  <systemHeader></systemHeader>
  <{DTO명}> ... </{DTO명}>
</message>
```

`pfmAppName`은 네 서비스 모두 `FS-DIS2`로 같다. 바뀌는 것은 `pfmSvcName`·`pfmFnName`·DTO뿐이다.

### 1-1. 공시 목록 — `DISFundFTimeAnnSO.selectAnn`

DTO는 `DISFTimeAnnInsDTO`.

| 파라미터 | 값 | 설명 |
|---|---|---|
| `uGb` | `1` | 전체(정기+수시). **`2`·`3`은 0건을 돌려준다** |
| `vStrtDt` / `vEndDt` | `YYYYMMDD` | **한 번에 1년 미만.** 서버가 강제하며, 넘기면 **오류가 아니라 0행**이 온다 (아래 실측) |
| `uCdList` | 빈 값 | 펀드 지정. 비우면 전체 |
| `gbOption` | `S` | `S`=펀드선택 / `N`·`F`=펀드명 |
| `uRptList` / `tsCd` | 빈 값 | 보고서 유형 |
| **`uRptAllYN`** | **`1`** | `tsCd`가 비면 **반드시 `1`**. `0`이면 **오류 없이 0건** |
| `companyCd` | 빈 값 | 운용사 지정. 비우면 전체 |

**응답**: 행 요소는 `<list>`, 그리드 컬럼 20개. 쓰는 것은
`standardDt` `uFundNm` `koreanNm` `standardCd` `companyCd` `tsCd` `txCd` `txVsn`
`announceTtl` `seq` `tmpV1` `uRptGb` `Status_GB`.

**자연키**는 `(companyCd, standardDt, announceTtl, tmpV1)`. **`tmpV1`을 빼면 안 된다** —
같은 날 같은 제목의 서로 다른 펀드가 한 묶음으로 뭉갠다(표본에서 펀드 72종 234행이 한 덩어리가 됐다).

**그런데 `tmpV1`의 의미가 공시 유형에 따라 바뀐다 (`12` 5절)**: 수시공시에서는 모펀드 코드,
정기공시에서는 자기 코드다. 그리고 **`ZZZZZZ…`는 결측이 아니라 모펀드 행 표시자다.**
결측으로 보고 지우면 위 자연키가 깨진다.

**수시/정기 판별**: `uRptGb`가 `O`(수시) / `R`(정기)이고, `tsCd` 접두 `2OF` / `2RF`와
**100% 일치한다**(`12`). 응답만 보고 수시를 거르는 유일한 수단이다.
클래스 행은 `uFundNm`이 `└▶`로 시작한다.

**증분 축**: `standardDt`. 룩백 일수는 `03`.

### 조회 창 실측 (09-20) — 「1년 지나면 영구히 잃는다」는 틀렸다

미확인 10을 호출 7회로 닫았다.

| 요청 기간 | 결과 |
|---|---|
| 1개월 `20260815~20260915` | 6,845행 (5.7MB) |
| 6개월 `20260315~20260915` | 125,069행 (104MB) |
| 11개월 `20251015~20260915` | 225,177행 (186MB) |
| **정확히 1년** `20250915~20260915` | **0행** (657바이트) |
| 1년+1일 / 1년+1개월 | **0행** |
| **2년 전 3일치** `20240813~20240815` | **2,044행** |

**사실 둘.**

1. **제약은 「한 번에 조회하는 기간 폭」이지 소급 한계가 아니다.** 2년 전 구간도 그대로 온다.
   **받지 않고 1년이 지나면 영구히 못 받는다는 것은 사실이 아니다.** 백필은 언제든 가능하며,
   **1년 미만 창으로 쪼개면 된다.** 경계는 1년 미만이고 정확히 1년부터 0행이다.
2. **초과를 조용히 실패한다.** HTTP 200, `</root>` 정상, 657~754바이트 빈 응답이고 오류 메시지가 없다.
   `uRptAllYN` 함정과 **같은 패턴**이다. 백필 스크립트가 넓은 창으로 돌면 「그 기간엔 공시가
   없었다」로 잘못 읽는다. **창 폭 검증을 코드에 넣어야 한다.**

실무 권고: 응답이 6개월에 104MB, 11개월에 186MB다. **1개월 단위 분할**이 현실적이다.

### 1-2. 첨부 목록 — `DISFtimeDetSO.select`

DTO는 `DISFtimeDetOutputListDTO`. 파라미터는 1-1 응답 행에서 그대로 가져온다:
`companyCd` `standardDt` `standardCd` `txCd` `txVsn` `seq`, 그리고 `uGb`는 **`F` 고정**.

**응답**: `<file>` 노드 안에 `<list>` 행으로 첨부가 온다. 필드는
`fileNm`(서버 저장명) · `serverPath` · `originalFileNm`(사람이 보는 한글 파일명).

**함정**: `txVsn=0`으로 보내면 서버가 **SQL 예외**를 돌려준다(`12`). 목록 응답의 값을 그대로 쓴다.

**다운로드**:

```
GET https://disdown.kofia.or.kr/COMFSFileDownload.jsp
    ?serverPath={serverPath}&serverFileNm={fileNm}&filename={originalFileNm}
Referer: https://dis.kofia.or.kr/
```

**쿼리값 셋을 각각 URL 인코딩해야 한다**(`quote(safe="")`). `originalFileNm`이 한글이라
인코딩 없이 붙이면 실패한다.

응답이 주는 `fileNm`은 **서버 저장명**이라 내려받기 전에 같은 파일을 가릴 수 있다.
중복 판정을 무엇으로 할지는 `02`가 정한다.

### 1-3. 판매회사 마스터 — `DISMngCompInqSO.select`

DTO는 `DISMngCompInqListDTO`. `option=S2`, `standardDt={YYYYMM}`. 응답 행 요소는 `<list>`,
쓰는 필드는 `saleCompCd`·`koreanNm`. **약 200곳.**

### 1-4. 판매사별 펀드 — `DISSalesCompFeeCmsSO.select`

DTO는 `DISCondFuncDTO`. `tmpV11`=판매사코드, `tmpV30`=기준일(`YYYYMMDD`), 나머지(`tmpV12`·`tmpV3`·`tmpV5`·`tmpV4`)는 빈 값.

**응답 행 요소가 `<list>`가 아니라 `<selectMeta>`다.** 금투협의 다른 서비스와 다르다.
필드는 `tmpV17`=표준코드, `tmpV18`=운용사코드, `tmpV2`=펀드명, `tmpV4`=설정일, `tmpV16`=기준일.

**응답 사실**: 「상장지수」를 포함하는 행이 **0건**이다. 이것이 조인에 무엇을 뜻하는지는 `14` 4절.
전체 순회는 200곳 × 평균 3,000건 ≈ 60만 행이므로 호출 간격 1초를 둔다(9절).

## 2. 공공데이터포털 — 펀드상품기본정보

```
GET https://apis.data.go.kr/1160100/service/GetFundProductInfoService/getStandardCodeInfo
    ?serviceKey={키}&numOfRows=1000&pageNo={n}&resultType=json
```

- **인증**: `DATA_GO_KR_API_KEY`. `serviceKey`는 **URL 인코딩하지 않는다**(`safe=""`로 encode).
- **페이징**: `numOfRows` 최대 1,000. `response.body.totalCount`까지 `pageNo`를 올린다. 184페이지.
- **응답**: `response.body.items.item`. **1건일 때 배열이 아니라 객체로 온다** — 리스트로 감싸야 한다.
- **쓰는 필드**: `srtnCd`(단축코드 5자리) `asoStdCd`(표준코드) `fndNm` `setpDt` `fndTp`
  **`prdClsfCd`**(상품 표 `product_class_code`로 확정, `01`).
- **실측**: 183,649건(2026-09-19). 펀드 1개당 1행이며 **클래스와 사모를 포함한다**.
- **`srtnCd` 값의 성질**: 형식은 `[A-Z0-9]{5}` 전건 일치이고 `srtnCd == asoStdCd[6:11]`이 성립한다.
  **전역 유일이 아니다.** 겹치는 규모와 그것이 안전한 이유는 `14` 2절(수치는 재측정하면 달라진다).
- **`setpDt` 값 함정**: 결측은 0.00%지만 **`11111111` 더미가 5건** 있고 연도 범위가 1111~2026이다(`14`).
- **증분 (09-20 실측, 미확인 11 해소)**: `beginBasDt`와 `basDt`가 **둘 다 동작하고 의미가 다르다.**

  | 요청 | `totalCount` |
  |---|---|
  | 파라미터 없음 (전건) | 183,649 |
  | `beginBasDt=20260901` | **2,354** (그 날짜 **이후 전체**) |
  | `basDt=20260901` | **376** (그 **하루**) |

  증분 수집에는 `beginBasDt`를 쓴다.
  **`setpDt`는 과거 날짜라 워터마크로 쓰면 안 된다**(`03`).

## 3. KRX — ETF 일별매매정보

```
GET https://data-dbg.krx.co.kr/svc/apis/etp/etf_bydd_trd?basDd={YYYYMMDD}
Header: AUTH_KEY: {키}
```

- **인증**: `KRX_API_KEY`. **발급과 승인이 별개다.** 키를 받아도 서비스별로 이용 승인을 따로 받아야 한다.

| 응답 | 뜻 |
|---|---|
| `{"respMsg":"Unauthorized **Key**"}` | 키가 없거나 틀림 |
| `{"respMsg":"Unauthorized **API Call**"}` | 키는 맞으나 **해당 서비스 승인이 없음** |

  **두 메시지를 구분해야 원인을 안다.**
- **응답 구조 (09-20 실측, 미확인 12 해소)**: 루트 키는 **`OutBlock_1`** 하나이고 그 값이 행 배열이다.
  행 필드는 **19개** — `BAS_DD` `ISU_CD` `ISU_NM` `TDD_CLSPRC` `CMPPREVDD_PRC` `FLUC_RT` `NAV`
  `TDD_OPNPRC` `TDD_HGPRC` `TDD_LWPRC` `ACC_TRDVOL` `ACC_TRDVAL` `MKTCAP`
  `INVSTASST_NETASST_TOTAMT` `LIST_SHRS` `IDX_IND_NM` `OBJ_STKPRC_IDX` `CMPPREVDD_IDX` `FLUC_RT_IDX`.
  쓰는 것은 `ISU_CD`·`ISU_NM`이고, `NAV`·`MKTCAP`·`LIST_SHRS`는 규모 지표로 쓸 수 있다.
- **`ISU_NM`은 정식 펀드명이 아니라 상장 약명이다** (`1Q 200액티브` vs `하나1Q200액티브증권상장지수투자신탁[주식]`).
  공공데이터포털과 **완전일치율이 0.0%**다. 포함매칭으로도 80.4%가 천장이다(`13` 4절).
- **실측**: 1,167건(2026-09-04 기준일).
- **증분 축**: `basDd`가 일자 단위 조회다. 적재 주기와 보관 범위는 `03`이 정한다(전건 스냅숏).
- **소급 범위 실측 (09-20, 미확인 5 해소): 최소 10년.**

  | 기준일 | ETF 종목 수 |
  |---|---|
  | 2016-09-02 | 226 |
  | 2021-09-02 | 502 |
  | 2024-09-02 | 881 |
  | 2025-12-01 | 1,048 |
  | 2026-06-01 | 1,130 |
  | 2026-09-04 | 1,167 |

  **「오늘 안 받으면 재구성할 수 없다」는 ETF에는 해당하지 않는다.** 과거 일자를 그대로 주므로
  일별 스냅숏은 나중에 몰아 받아도 된다. 상장폐지 판정용 차집합도 과거 구간에서 만들 수 있다.
  적재 주기·보관 범위 결정을 서두를 이유가 없어졌다(`03` 반영).
- **우회로 없음**: `data.krx.co.kr`의 비공식 `getJsonData.cmd`는 세션을 요구해 `LOGOUT`만 준다.

## 4. DART

### 4-1. 공개 뷰어 — 인증 불필요 (실호출 확인)

```
GET https://dart.fss.or.kr/dsaf001/main.do?rcpNo={접수번호}
```

좌측 문서 트리를 만드는 **인라인 `<script>` 안에 노드 배열이 서버 렌더링되어 있다.** AJAX가 아니다.
`node1['dcmNo'] = "…"` 형태로 한 줄에 하나씩 박혀 있어 정규식으로 뽑는다(`09`).
필요한 값은 `dcmNo`·`eleId`·`offset`·`length`·`dtd`다.

```
GET https://dart.fss.or.kr/report/viewer.do
    ?rcpNo=&dcmNo=&eleId=&offset=&length=&dtd=dart4.xsd
```

- **표지 노드를 `eleId` 번호로 찾으면 안 된다 (`01` 결정).** 원본은 `eleId=1`이 표지이고,
  [기재정정]은 정정신고 노드가 앞에 붙어 `eleId=2`가 표지다. 고정 번호로 읽으면
  **원본과 정정본 중 하나는 반드시 틀린다.** 노드 텍스트 **「투 자 설 명 서」**로 찾는다(`09`).
- 위험등급은 표지 노드 안에서 `「n등급[문구]」` 표기(`08` A1). 띄어쓰기 변형이 있다.
`viewer.do` 호출에는 **Referer가 필요하다**(`09`).

### 본문 PDF — 채점 대상은 여기 있다

「[ 본 문 ]」 요소는 **PDF 링크 한 줄**이다(10건 전부). 실제 본문은 별도로 받는다.

```
GET https://dart.fss.or.kr/report/download.do?dcmNo={dcmNo}&flNm={파일명}
```

실측에서 HTTP 200 · `application/pdf` · 718,944바이트가 왔다(`09`·`02`).
**수집 실패 판정은 `Content-Type != application/pdf`다**(`03`).

**DART가 절(`eleId`) 단위로 주는 것은 표지와 변경요약뿐이고 본문은 PDF 한 덩어리다.**
절 단위 분할이 필요하면 PDF 파싱 단계가 따로 있어야 한다.

- 목록 진입점 `https://dart.fss.or.kr/dsac001/mainF.do`는 서버 렌더링 HTML 표라 바로 파싱된다.
- **목록을 API로 받는 경로(`pblntf_detail_ty` G001~G003 필터)의 엔드포인트·파라미터는 저장소에 없다.**
  `03`·`01`이 필터 값만 적고 호출 방법을 적지 않았다 → 10절 미확인 9.
- **실측**: 투자설명서 10건 중 표지 펀드코드가 **10/10** 존재. ETF 3건 포함(`09`).
- **판매회사 명단은 표지에 없다**(`09`). 판매사는 금투협에서 받는다(1-4).

### 4-2. OPEN DART API — **미호출**

```
GET https://opendart.fss.or.kr/api/document.xml?crtfc_key={키}&rcept_no={접수번호}
```

인자는 둘뿐이고 응답은 zip이다. **가이드 페이지만 인증키 없이 읽었고 실제 호출은 못 했다**(`09`).

**확인 불가로 남긴 것**: zip 안에 XML만 있는지, PDF 등 첨부까지 들어있는지.
가이드 본문에 이를 명시하는 문장이 끝내 없었다. 추정으로 설계하지 말 것.

**증분 축**: `rcept_dt`. 룩백 일수와 그 이유(정정본)는 `03`.

## 5. 금감원 OPEN API — 검사결과제재 · 경영유의사항 등 공시

**두 API는 같은 표의 두 뷰다.** 요청 변수도 결과 필드 13개도 이름까지 같고, 예시의
`examMgmtNo`가 동일하다. 다른 것은 경로와 구분 필드뿐이다(`14` 6절).

```
GET https://www.fss.or.kr/fss/kr/openApi/api/openInfo.jsp        # 검사결과제재
GET https://www.fss.or.kr/fss/kr/openApi/api/openInfoImpr.jsp    # 경영유의사항 등
    ?apiType={xml|json}&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&authKey={32자리}
```

**요청 변수는 넷뿐이다.** 금융회사도 업종도 **페이지도 없다**.

**결과 필드 13개**: `emOpenNo`(제재정보번호) `examMgmtNo`(검사관리번호) `transCode` `emOpenSeq`
`actGbn` **`finInstName`(금융회사)** `actReqDate`(제재조치일) `actOrganCon` `actOfficerCon`
`actEmpCon` `actObjContent`(제재대상사실) `inputDate` `inputMan`.

| 함정 | 내용 |
|---|---|
| **JSON 루트 키가 `reponse`** | `response`로 짜면 전건 0으로 조용히 실패한다. **실호출로 확정 (09-21)** |
| **페이징 없음** | 5,700여 건 백필은 **기간 분할**로만 가능 |
| **`emOpenSeq`는 워터마크가 아님** | 검사 1건 안의 순번이고 요청 변수에도 없다. 증분은 날짜로만 |
| 날짜 형식 3종 | 요청 `YYYY-MM-DD` / `actReqDate` `2026.04.24` / `inputDate` `2026-04-27 10:14:12` |
| **`result` 단건 시 객체 가능성** | 공공데이터포털과 같은 함정을 예상해 스크립트가 방어해 두었으나 **09-21까지도 실제 단건 응답으로는 미검증** (받은 것은 0건과 8건뿐, 내용은 미회수 — 아래) |
| 기간 분할 폭 | **정정 (09-21 실측). 90일은 틀렸다.** 개인용 키는 **한 호출 최대 1개월**만 허용한다. 넘기면 `resultCode=030`(「최대 조회기간 초과(개인 : 1개월)」). `fetch_fss_sanctions.py`는 `CHUNK_DAYS=28`로 고쳤다. **법인 키의 상한은 미확인** |
| **응답 인코딩이 `euc-kr`** (신규, 09-21) | `Content-Type: text/html;charset=euc-kr`. `utf-8`로 디코드하면 `resultMsg`·`finInstName`·`actObjContent` 등 한글 필드가 전부 깨진다(치환문자로 뭉갬). 이전 스크립트는 `utf-8` 고정이었다 — 고쳤다 |
| **`resultCode`는 성공/실패 2분법이 아니다** (신규, 09-21) | `1`=정상(0건 포함 가능) / `900`=그 구간 자료 없음(**정상, 에러 아님**) / `030`=조회기간 상한 초과 / `033`=**일일 조회 건수 초과**. 이전 스크립트는 `1`이 아니면 전부 예외로 던져 `900`(빈 결과)도 실패로 오판했다 — 고쳤다 |
| **일일 조회 건수 30회** (신규, 09-21) | `resultCode=033`, 메시지 「하루 조회 건수를 초과하였습니다. 하루 조회 건수는 30회 입니다.」. **`sanction`·`impr` 두 엔드포인트가 같은 키의 한도를 공유한다**(양쪽에서 실측). 초기화 시점은 미확인(달력일 자정 추정) |
| **상품 칸이 없음** | 13개 필드 어디에도 상품 식별자가 없고 본문 `actObjContent`도 `㉮펀드`·`甲`·`A지점`으로 마스킹이다. 스키마에 미치는 결과는 `01` J12·`14` 6절 |

**인증키**: 32자리. **개인 신청과 법인 신청의 경로가 다르고, 법인 키에만 요청 IP 등록이 붙는다.**
수집 서버 IP가 정해지기 전에 법인 키를 신청하면 재신청해야 한다.
**09-21에 개인용 키가 발급되어 실호출을 시작했다.** 조회기간 1개월 상한은 이 개인 키 등급의 값이며,
법인 키를 받으면 재확인해야 한다.

**09-21 실호출 요약**: 최근 24개월을 월 단위로 훑어 **2026-09에 `resultCnt=8`**을 확인했다
(그 외 월은 `900`=자료 없음). **탐색 호출 자체가 일일 한도 30회를 다 써버려, 2024-10 이전
구간은 더 조회하지 못하고 `033`으로 끊겼다** — 그 달들에 자료가 없다는 뜻이 아니라 단지
그날의 조회 기회가 바닥났다는 뜻이다. **8건의 실제 필드 내용(값 표기·이상값·본문 마스킹 수준)도
같은 이유로 받지 못했다.** 다음 조회 가능일에 `--from 2026-09-01 --to 2026-09-30` 한 호출로
받을 수 있다(이미 존재가 확인됐으므로 탐색 호출 없이 바로 됨).

**미확인 넷** (10절 2·3·4·13번. 다음 조회 가능일에 `--probe`와 실호출로 닫을 것):
`startDate`가 `actReqDate`에 걸리는지 `inputDate`에 걸리는지(09-21 `--probe` 시도 자체는
성공했으나 대상일 2026-04-24가 `900`이라 판정 불가) / 경영유의사항 본문의 실제 마스킹 수준 /
`emOpenNo`가 두 소스에 걸쳐 유일한지 / 한 응답의 건수 상한(`resultCnt=8`은 관측했으나 이보다
큰 응답을 아직 못 받아봤다).

## 6. 금감원 분쟁조정결정례 — 게시판 + HWP

API가 없다. 게시판 `B0000390`이며 **본문이 비어 있고 HWP 첨부만 준다.**

HWP 5.0은 OLE 복합문서다. `BodyText/Section0`을 **zlib raw deflate(`-15`)**로 풀고
`HWPTAG_PARA_TEXT`(태그 67) 레코드에서 UTF-16LE 텍스트를 꺼낸다.
`scripts/hwp_text.py` + `scripts/_ole.py`가 외부 의존성 없이 처리한다.
**버전 판별은 OLE 시그니처 `D0CF11E0…`로 한다** — 없으면 HWP 5.0이 아니다.
`PrvText`는 압축 없는 UTF-16LE 평문이라 본문이 막혔을 때의 대체 경로가 된다.

| 한계 | 내용 |
|---|---|
| **HWP 3.0은 읽지 못한다** | OLE가 아니라 자체 바이너리다. 첨부 213단위 중 **94건**(1999~2004년)이 여기 해당 |
| 「상위 버전 배포용 문서」 | `BodyText`가 안내문뿐이다. `--preview`로 `PrvText`(약 1,000자)를 건지는 것이 최선 |

**조인 불가**: 상품명뿐 아니라 **판매사명도 마스킹**이다(`●●증권`). 업종만 남는다(`14` 5절).

**재현 확인 (09-20)**: `nttId=219340`의 첨부를 받아 `hwp_text.py`로 본문을 뽑아
`【 ○○○ : ●●증권 】` 마스킹까지 재현했다. `14` 5절의 결론이 그대로 성립한다.
역추적의 출발점이 된 `nttId` 8건은 `14` 5절 표에 있다.

## 7. 국가법령정보 — **미호출**

`LAW_API_OC`가 비어 있다. 무인증 호출이
`{"result":{"err_cd":"010","err_msg":"미등록 인증키","total_count":"0"}}`를 돌려준다는 기록이 있다.
**출처는 팀 Notion 조사(「[Study] 데이터 소스 6종」)이고 이 저장소의 실측이 아니다.**
엔드포인트도 남아 있지 않아 지금은 재현되지 않는다.

**다만 J13은 키를 받아도 풀리지 않는다.** 먼저 정해야 하는 것이 둘이다.

1. 금소법 19조의 **「설명서」**와 우리가 수집하는 **「투자설명서」**는 같은 서류가 아니다.
   대응 관계가 정의되지 않았다.
2. 고지충실도가 **점수 축인가 누락 검출 필터인가.** 팀 Notion EPIC 「금소법 19조 설명의무 점검표
   정의」는 「변별력이 거의 없을 것이므로 점수 축이 아니라 **누락 검출용 필터**로 성격을 고정한다」고
   적었다. `04`는 `score_type` 값으로 두고 있다. **저장소 밖 문서와의 대조이므로 `04` 전문 확인이
   먼저다** — 확정된 모순이 아니라 확인할 항목이다.

→ `01` 미확인 3. 인증키 신청보다 이 결정이 먼저다.

**증분 축**: `MST` 변경 여부가 미확인이라 조문 내용 해시로 대체한다. 정책은 `03`.

## 9. 공통 규칙

### 방어적 수집

호출 간격 **1초 이상**, 동시 요청 **1개**. 전체 순회가 60만 행 규모인 금투협 1-4에 특히 적용한다.

### 재시도

스크립트 공통: **3회**, 대기 2초·4초. 네트워크 오류와 파싱 오류를 함께 받는다.

### 응답 완전성 검증 — 소스마다 수단이 다르다

| 소스 | 검증 수단 |
|---|---|
| 금투협 | 응답이 **`</root>`로 끝나는지**. 끝나지 않으면 절단이다 |
| 공공데이터포털 | `totalCount`와 누적 건수 대조 |
| 금감원 OPEN API | **정정 (09-21).** `resultCode == "1"`만 정상이 아니다. `900`(그 구간 자료 없음)도 정상 — 예외로 올리면 안 된다. `030`(기간 상한 초과)·`033`(일일 30회 한도 초과)은 재시도해도 풀리지 않으므로 즉시 중단하고 `resultMsg`를 올린다 |
| KRX | `respCode` 키가 있으면 오류 응답이다 |

**절단을 잡지 못하면 파서가 행을 조용히 적게 센다.** 이것이 가장 비싼 실패다.

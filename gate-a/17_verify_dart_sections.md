# 17. DART 본문 PDF의 부·절 분할 실현성 (검증 3)

실측일 2026-09-20, 대현. 재현은 `scripts/dart_sections.py`.

```bash
python3 scripts/dart_sections.py 20260911000067
```

## 왜 쟀는가

**저장소 안에서 근거 셋이 정면으로 충돌한 채 방치돼 있었다.**

| 문서 | 주장 |
|---|---|
| `15` 4-1절 | 「DART가 절(`eleId`) 단위로 주는 것은 표지와 변경요약뿐이고 **본문은 PDF 파일 하나**다」 |
| `05-timeline.md` (PM) | 「DART 정형 HTML. **파싱 난도 하향**, 「파싱이 최대 난도」라는 전제 무효」 |
| `09-plan-review/02-data-engineer.md` | 「목차 태그 `h2`/`h3` 기준 분할… **규칙 기반으로 충분**」 |

그리고 **시도 기록이 한 건도 없었다.** 여기 걸린 것이 작지 않다 — 「원문 절 단위 분할과 소스별 실패율 산출」(10-01~10-14, **여유 0일**), 파이프라인 가동 점검 「문서 500건 이상 텍스트화」, `01`의 절 표와 점수 표 전체, 그리고 **최종 산출물 목표 1단계인 부·절별 채점**이다.

## 결론 먼저

| 물음 | 답 |
|---|---|
| 본문 PDF에 텍스트 층이 있는가 | **있다.** 스캔본이 아니다 |
| PDF에 북마크(목차)가 있는가 | **없다.** `/Outlines` 0건 |
| 부 단위로 쪼갤 수 있는가 | **된다. 5개 문서 전부 5/5** |
| 절 단위로 쪼갤 수 있는가 | **된다. 292/294 = 99.3%** (09-20 표본 확대분) |
| 외부 의존성 | **`pdftotext`(poppler) 하나.** 인증키는 필요 없다 |

**따라서 「본문이 PDF 파일 하나」는 맞지만, 그것이 절 분할을 막지는 않는다.** 세 주장 중 `15`가 사실을 정확히 적었고, 다른 둘은 결론(난도 하향 / 규칙 기반으로 충분)에서 우연히 맞았다 — 근거로 든 「정형 HTML」과 「`h2`/`h3` 태그」는 둘 다 존재하지 않는다.

## 2. 방법

1. `dsaf001/main.do?rcpNo=` 에서 문서 트리를 읽어 **「[ 본 문 ]」 노드**를 찾는다
2. `viewer.do` 로 그 노드를 받으면 **PDF 링크 한 줄**이다
3. `download.do` 로 PDF를 받는다 (`application/pdf`, 표본은 0.7MB / 65쪽)
4. `pdftotext -layout` 으로 텍스트를 뽑는다
5. 문서 앞의 **목차**에서 부별 절 제목을 읽고, 본문에서 그 제목을 찾아 경계로 삼는다

## 3. 함정 넷 — 전부 실측에서 걸렸다

### ① 트리 JS가 `var node1 = {}`을 노드마다 재사용한다

변수명으로 정규식을 걸면 **마지막 노드 하나만 잡힌다.** 블록으로 끊어 읽어야 한다.
처음에 이걸 몰라 「노드가 1개」라는 결과를 얻었다.

### ② 들여쓰기로 목차와 본문을 가를 수 없다

첫 구현은 「목차는 1열, 본문 표제는 들여쓰기」로 갈랐고 **5건 중 3건만 처리됐다.**
서식이 문서마다 다르다.

| 문서 | 목차 들여쓰기 | 본문 표제 들여쓰기 |
|---|---|---|
| 20260911000067 | 0칸 | 2칸 이상 |
| 20260911000035 | **0칸** | 15~25칸, 그리고 `제1부.` 처럼 **마침표가 붙는다** |
| 20260911000231 | **4칸** | 2~6칸 |

**대신 순서는 일정하다.** 제1~5부가 오름차순으로 한 번 나오면 목차, 다시 한 번 나오면 본문이다. 오름차순 묶음으로 끊는 방식으로 바꾸니 **5건 전부 5/5**가 됐다.

### ③ 목차 뒤에 다른 번호 목록이 이어진다

목차의 마지막 부 다음에 「투자자 유의사항」이나 「요약 정보(간이투자설명서)」가 붙고, 거기에도 `1.` `2.` 가 있다. 그대로 읽으면 **제5부 절이 6개에서 24개로 실제보다 커진다.**

**절 번호는 부 안에서 단조 증가한다.** 번호가 되돌아가면 목차가 끝난 것으로 보고 끊는다.

### ④ `file` 명령의 쪽수를 믿으면 안 된다

`file`은 표본 PDF를 「10 pages」라고 했지만 실제는 **65쪽**이다.

## 4. 남은 2건 (20260911000035)

원본 문서 하나(`20260911000035`)에서 절 2개를 못 찾았다. 목차 제목과 본문 표제의 표기가
다른 것으로 보이나 **확인하지 않았다.** 표본을 9건으로 넓혀도 못 찾는 절은 이 2건뿐이다(292/294).

**수동 확인 큐로 보내면 된다.** 못 찾은 절은 그 부의 나머지 구간에 포함되므로 텍스트를 잃지는 않는다.

## 5. 함의

### 부·절별 채점이 가능하다

`04`의 점수 표가 절 단위 저장을 전제하는데, **그 전제가 성립한다.** 파이프라인 가동 점검의 「문서 500건 이상 텍스트화」도 이 경로로 된다.

### 「원문 절 단위 분할」 티켓의 난도가 내려간다

10-01~10-14 여유 0일 작업인데, 핵심 로직은 이미 돌아간다. 남은 일은 **표본 확대와 실패율 산출**이다.

### 간이투자설명서가 같은 PDF 안에 있다 (새 발견)

표본 문서의 목차 뒤에 **「요약 정보 &lt;간이투자설명서&gt; 작성기준일…」**이 이어진다.
`12` 6절은 간이투자설명서가 「DART와 금투협 양쪽에서 온다」고 적었는데, **DART 쪽은 별도 문서가 아니라 투자설명서 PDF 안에 포함된 절**이다.

**소스 간 중복률 측정(2단계 데이터 파이프라인 Flow 설계 선행 과제)의 설계가 바뀐다.** 문서 단위 sha256 비교로는 이 중복이 잡히지 않는다. 금투협이 주는 간이투자설명서 PDF와 DART 투자설명서 **안의 요약 정보 구간**을 비교해야 한다.

### `pdftotext` 의존성이 생긴다

지금까지 저장소는 외부 의존성이 없었다(`hwp_text.py`도 순수 파이썬). **poppler는 예외로 받아들여야 한다** — PDF 텍스트 추출을 직접 구현하는 것은 범위 밖이다. 배포 환경에 poppler 설치를 요구 사항으로 올린다.

# 08. 소스 검증(web-verify) 결과가 설계에 미친 영향

09-14 대현. 옆 세션이 팀의 09-05~06 실측 주장 39건을 공식 문서·실제 DART 문서 트리로 검증한 결과(`web-verify.md`)를 읽고 01~07에 반영했다. 검증 자체는 옆 세션 산출물이며, 이 문서를 쓰면서 우리가 다시 확인한 항목은 없다. 근거 URL은 원문에 있다.

## 설계를 바꾼 항목

| 검증 항목 | 판정 | 무엇이 바뀌었나 | 반영 위치 |
|---|---|---|---|

## 설계에 새 질문을 만든 항목

- **D1·D2 finlife는 예금·대출·연금 API다.** 09-09 소스 4종의 「금융상품통합비교공시 `fin_prdt_cd`」가 펀드·ETF·ELS에 존재하는지 확인된 바 없다. 없으면 이 소스의 역할(무엇을 가져오는 소스인가)을 09-16에 다시 정해야 한다. → 01 미확인 12, 07 항목 3.
- **ELS의 상품 식별 코드.** 펀드코드는 집합투자증권 체계라 ELS(증권신고서·일괄신고 계열)에는 없을 가능성이 크다. ELS 조인 키가 무엇인지 별도 확인 필요. → 01 미확인 13.

## 우리 설계와 무관한 항목

F2(위험등급 산정 기준 4축이 아님)는 우리가 등급 산정 모델을 만들지 않고 값만 저장하므로 영향 없음. D1(crdt_grad 번호 불연속)은 대출 API 사안. F1·F4·F5(법령 조문 수·시행일·정보통신망법)는 국가법령정보 연결(01 미확인 3)이 정해질 때 참조. B3·B4·B5(금투협 화면·API 범위)는 수집 층 구현 사안.

## 반영하지 않은 권고

- F2 「정량 9개·정성 6개 요소를 담는 구조로 스키마를 다시 잡아야」 → 우리는 위험등급 값을 소비할 뿐 산정하지 않는다. 채택하지 않음.
- F3 「산정 주체 필드를 두어야」 → 현재 소스가 DART 표지 하나라 값이 상수다. 판매사 산정 등급 소스가 생기면 그때 추가.

## 09·10 실측 결과 반영 (09-14 밤)

web-verify를 그대로 믿지 않고 두 항목을 우리가 다시 확인했다. 결과 파일은 `09_verify_dart_cover.md`(DART 표지 10건, 공개 뷰어 curl)와 `10_verify_finlife_codes.md`(finlife·코드 체계, 웹 조사) + 대현 보충.

| 확인한 것 | 결과 | 설계 반영 |
|---|---|---|
| 표지 펀드코드 존재 | 10/10 (운용사 4곳, ETF 3, 정정본 6) | short_code를 1차 키로 확정 |
| 펀드코드 형식 | 5자리 영숫자. 「영문 1 + 숫자 4」가 아님(CY091, AT146, EZ258) | 형식 검증 `[A-Z0-9]{5}` |
| 표지의 판매회사 | **명단 없음**, 안내 문구만. web-verify A1의 「표지에 판매회사」는 틀림 | 상품_판매사 표는 유지, 소스는 미확인 16으로 |
| 표지 노드 위치 | 원본 eleId=1, 정정본 eleId=2 | 노드 텍스트로 찾기. treeData 추출 절차 |
| 위험등급 표기 | 「n등급[ 문구 ]」 공백 불규칙 | `(\d)등급` 정규식 |
| 최초제출일 문구 | 「정정대상 공시서류의 최초제출일 : 2023년 07월 31일」 실측 | initial_submit_date 파생 확정 |
| zip에 PDF 동봉 | 가이드에 명시 없음. 키 필요 | 미확인 14 유지 |
| finlife 상품 범위 | 오픈 API 8종, 펀드·ETF·ELS 없음 | fin_prdt_cd는 펀드 조인 키 아님. 소스 유지 여부는 09-16 결정 |
| 금투협 운용사 코드 | 3자리 영숫자, 536건 표 확보 | ref_kofia_mgmt_codes.csv. 「운용사코드 6자리」는 부정확 |
| K55301 = 미래에셋 | 표로 확인. 팀 주장이 맞았고 web-verify B1 「근거 없음」이 해소 | 10 보충 |
| ELS 식별 | 회차 번호 / KR6… / 일괄신고추가서류 후보. 정황 수준 | 09-16 안건 |

## web-verify에서 우리 실측과 어긋난 항목

- A1 「표지(위험등급·명칭·판매회사·작성기준일·효력발생일)」: 판매회사는 표지에 없다. 나머지는 맞다.
- B1 「K55301이 미래에셋이라는 근거를 찾지 못했다」: 금투협 운용사코드 표에서 301 = 미래에셋자산운용. 팀의 원래 기록이 맞았다.
- B1 「운용사코드 6자리」: 3자리다. `K55`는 고정 접두어로 보인다(확인된 사례 4건 모두 K55, 전수는 미확인).

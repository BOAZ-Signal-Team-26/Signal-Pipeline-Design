# 03. 수집·파싱 실패 처리 규칙 — 2026-09-22 재검토안

수집 요청, 응답 파일, 실행별 추출, 절의 상태를 분리한다. 점수 계산 가능 여부는 추출 성공 여부와 다르다. 과거의 「0건=실패」「500자 미만=실패」를 그대로 구현하지 않는다.

## 1. 수집 결과

| collection_attempt.outcome | 판정 | 처리 |
|---|---|---|
| SUCCESS | 정상 업무 코드, 응답 구조·완전성 검증 통과 | 원본 저장/기존 파일 참조 |
| EMPTY | 유효한 조회 조건에서 정상 자료 없음 | 성공한 조회로 기록, 행 0건 자체를 실패로 세지 않음 |
| RETRYABLE_FAILED | 타임아웃·일시적 5xx | 같은 run_id, attempt_no 증가 |
| PERMANENT_FAILED | 잘못된 요청/폐기 URL 등 재시도로 해결 불가 | 원인 수정 전 자동 반복 중단 |
| CONFIG_ERROR | 401/403, 승인/키 설정, 필수 요청값/조회창 누락 | 설정 확인. 같은 요청 자동 반복 안 함 |
| RATE_LIMITED | HTTP 429, API 일일/분당 한도 | Retry-After/확인된 한도 복구 뒤 재개. 영구 자료 없음으로 처리하지 않음 |

HTTP 상태와 업무 응답 코드를 별도 칼럼에 저장한다. 타임아웃은 `http_status=NULL`, 바이트가 없으면 `raw_object_id=NULL`이다. 파일이 있으면 실패 응답도 02 규약대로 보존하며 raw.collect_status로 후속 처리 대상에서 제외한다.

### 소스별 검증

| 소스 | 주의 |
|---|---|
| 금감원 | `resultCode=1` 정상, `900` 정상 빈 결과, `030` 조회창 수정, `033` 한도 복구 대기. 문자열로 보존 |
| 금투협 | `uRptAllYN` 등 필수 인자·1년 미만 조회창을 **요청 전에** 검증. 잘못된 요청의 0행을 정상 EMPTY로 승인하지 않음 |
| 금투협 | 종료 태그·총건수/수신 행 수 대조. 정기공시를 수시 4필드로 접지 않음 |
| 포털 | 업무 코드 확인 후 객체/배열 item 정규화, 전체 페이지 수신과 totalCount 대조 |
| KRX | 승인/키 오류 구분, 요청 기준일·응답 구조 검증. 휴장/수집 실패/불완전 응답을 상장폐지로 해석하지 않음 |
| DART | 목록/원문 API의 업무 오류와 HTML 뷰어 경로를 구분. PDF는 MIME과 실제 형식 확인. API ZIP 내부 구성은 아직 미확인 |

정상 빈 응답과 전송 바디 0바이트는 다르다. 0건이 불가능하다고 생각되는 구간은 이전 분포/요청 조건을 근거로 품질 경보를 낼 수 있지만 전 소스 공통 실패 규칙으로 확정하지 않는다.

## 2. 재시도와 워터마크

기존 잠정 정책의 타임아웃·5xx 지수 백오프 최대 5회는 유지한다. 429는 예외로 한도 정책을 따른다. 403/키·서비스 승인 문제는 자동 재시도하지 않는다. 예제 조사 스크립트의 3회 재시도는 생산 수집 계약이 아니다.

워터마크는 해당 구간의 요청·페이지 완전성 검증이 끝났을 때만 전진한다. 정상 EMPTY와 실패/한도 중단을 구분하고 중간 페이지까지 받고 성공으로 승인하지 않는다.

| 소스 | 증분/스냅숏 축 | 주의 |
|---|---|---|
| DART | rcept_dt | 기존 3일 룩백 잠정값. 접수/원본/첨부 처리 단계 분리 |
| 포털 | basDt, 요청 beginBasDt | setpDt는 설정일이므로 워터마크 아님 |
| KRX ETF | basDd/BAS_DD 일별 전체 | 일별 파일 보존. 완전한 거래일 자료만 차집합 비교 |
| 금투협 공시 | standardDt, 기존 7일 룩백 | 백필은 1개월 창 권고, 수시공시만 4필드 묶음 |
| 금투협 판매관계 | 월 기준 + 실제 조회일 | 월 대표일·전건 성공 여부를 함께 보존 |
| 금감원 제재 | inputDate | actReqDate는 사건일. 표본 중 구간 밖 사건일/구간 안 입력일 사례로 확인; 표본 확대 재검증 필요 |
| 분쟁조정 | 게시판 ID + 게시글 번호 | 상품·법인 마스킹은 수집 실패가 아님 |
| 국가법령 | 원천 계약 확인 전 미정 | 조문 해시 후보, 법적 서류 대응을 먼저 확인 |
| finlife | 현 CDI 핵심 범위 제외 | 펀드·ETF·ELS 상품 마스터로 사용하지 않음 |

금감원 API에서 과거 조회가 0건이라는 결과를 「그 기간에 제재가 없었다」로 쓰지 않는다. 저장 표본은 2026-09 8건이며, 게시판과 API의 범위 차이는 별도 조사 대상이다. API가 항상 최근 한 달만 제공한다는 서버 정책은 확인되지 않았다. 라벨 소스 전환은 팀 과제이며 이번 수정에서 크롤러를 전환하지 않았다.

## 3. 파일 추출과 절의 품질

추출 결과는 `file_extraction(raw_object_id, run_id)`에 보존한다. 기존 raw_object.extract_status의 단일 현재값은 사용하지 않는다.

| extract_status | 의미 |
|---|---|
| EXTRACT_OK | 원래 있는 텍스트가 정상적으로 추출됨 |
| EXTRACT_FAILED | 일반 추출 실패. 사유 보존 |
| EXTRACT_UNSUPPORTED_FORMAT | 지원하지 않는 형식(HWP 3.0 등) |
| EXTRACT_PARTIAL | 일부만 복구됨. 전체 본문 성공으로 세지 않음 |
| OCR_CANDIDATE | OCR 경로가 필요한 입력. 자동 성공 아님 |
| EXTRACT_NOT_APPLICABLE | 본문 추출 대상이 아닌 표지/API metadata 등 |

파일 전체가 예상보다 짧거나 깨진 문자 비율이 큰 것은 품질 의심 신호다. 기존 500자/30%는 미검증 잠정값이며 **모든 절에 적용하는 실패 기준이 아니다.** 짧은 절은 실제로 존재하므로, 정상 추출이면 EXTRACT_OK를 유지하고 `quality_flags`에 SHORT_TEXT를 남긴다. 구체 문자수 임계값과 문장/어절 분모는 DS가 정한다.

- 500자 미만이어도 정상적인 짧은 절을 버리지 않는다.
- 깨진 문자 30% 규칙은 Unicode/표·수학기호가 있는 금융문서에서 재검증해야 한다.
- 파일 전체 추출 성공과 절 경계 찾기는 별도 검증이다. CSV의 292/294는 경계 찾음이지 모든 텍스트 품질의 성공률이 아니다.
- `section_text`는 실패 시 복구 문자열 또는 NULL을 허용한다. 「실패해도 본문이 항상 있다」고 가정하지 않는다.
- ASL의 표 제거와 고지 충실도의 표 보존은 지표별 파생 처리다. canonical text 자체에서 표를 지우지 않는다.
- `EXTRACT_OK`는 채점의 필요조건이며 충분조건이 아니다. 분모 0·짧은 절·미정 산식은 계산 상태/사유로 다룬다.

## 4. 문서 파싱 상태는 실행별 뷰

`(document_id, run_id)`에서 **그 실행이 선택한 파일 버전과 채점 대상 역할 집합**만 집계한다. 과거 파일 버전 전체를 세지 않는다. 대상 목록은 입력 manifest에 고정한다.

우선순위는 다음과 같다.

1. CDI 비대상 문서: PARSE_NOT_APPLICABLE.
2. 파일 선택·필수 수집·추출이 아직 끝나지 않음: PARSE_PENDING.
3. 대상 집합이 비어 있지 않고 전부 EXTRACT_OK: PARSE_OK.
4. 평가 완료 후 하나 이상 EXTRACT_OK 또는 EXTRACT_PARTIAL: PARSE_PARTIAL.
5. 평가 완료 후 정상/부분 텍스트가 전혀 없거나 필수 파일이 영구 수집 실패: PARSE_FAILED.

따라서 빈 집합에서 「모두 성공」으로 계산하지 않으며, 부분 복구만 있는 경우가 PARTIAL과 FAILED 양쪽에 동시에 해당하지 않는다. cover_html/cover_xml 등 본문 비대상 파일은 본문 상태 집계에서 제외하되 위험등급/코드 추출 품질은 별도로 추적한다.

파일 단위 집계와 절 단위 품질은 별도다. 문서 PARSE_OK만 보고 실패한 절을 채점하지 않는다. 재처리 스케줄·큐 구현은 Gate B 책임이다.
